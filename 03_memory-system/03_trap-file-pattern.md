# 「즉시 참조 함정」 파일 패턴

도메인에서 반복해서 걸려 넘어지는 함정을 한 파일에 한 줄씩 모아, 메인 세션과 **서브에이전트가 모두 항상 읽게** 하는 패턴.

## 왜 따로 두나

- 함정은 처음에 메모리 인덱스 맨 위 절에 있었다. 인덱스는 메인 세션만 자동으로 읽는다.
- 위임받은 에이전트는 메모리를 보지 못한다. 그래서 메인이 아는 함정을 구현 담당 에이전트가 다시 밟았다.
- 프로젝트 rules 폴더(`<workspace>/.claude/rules/`)의 파일은 항상 로드된다. 함정을 그리로 옮기고 인덱스에는 포인터 한 줄만 남겼다.
- 다른 종류의 에이전트(AGENTS.md를 읽는 도구)에는 「작업 전에 이 파일을 읽는다」를 규칙 파일에 적는다.

## 파일 규칙

| 규칙 | 이유 |
|---|---|
| 한 함정 = 한 줄(불릿). 30~40줄을 **상한**으로 둔다. 상한에 닿으면 새 줄을 넣기 전에 낡은 줄을 합치거나 상세 파일로 내린다 | 항상 로드되는 파일이다. 길어지면 묻힌다. 한 줄이 곧 매 세션의 비용이다 |
| **도메인·DB 함정만** 넣는다. 작업 방식 규칙은 넣지 않는다 | 처음 옮길 때 작업 방식 줄이 섞여 들어갔고, 그중 하나는 이미 뒤집힌 옛 규칙이었다 |
| 줄마다 상세가 있는 메모리 파일을 포인터로 단다 | 한 줄로는 조건과 예외를 다 못 담는다 |
| 중요도 표시(★)는 실제 사고가 난 것에만 | 전부 강조하면 강조가 없다 |
| 근거가 된 날짜를 괄호로 남긴다 | 왜 생겼는지 추적할 수 있다 |
| 메모리에 적힌 사실은 쓰기 전에 재검증하라는 줄을 포함한다 | 함정 파일 자체도 낡을 수 있다 |

## 좋은 함정 한 줄의 모양

```
- [강조] <조건: 어떤 상황에서> <하지 말 것 / 대신 할 것> — <한 구절 이유>(근거 날짜) → [[상세-메모리]]
```

함정의 유형별 예. **전부 지어낸 예시다**(가상의 구독 결제 서비스 — `subscriptions`·`invoices`·`usage_events` 같은 이름은 실제 스키마가 아니다). 원래 파일의 내용은 특정 업무에 묶여 있어 옮기지 않았고, 「어떤 종류의 줄이 들어가는지」만 보인다.

| 유형 | 예시 줄(가상) |
|---|---|
| 필터 함정 | `- 구독 이력 전체를 볼 때 is_current = true로 거르지 말 것 — 해지된 구독의 최초 가입 행이 빠진다 → [[subscription-history-filter]]` |
| 같은 값·다른 뜻 | `- ★상태값 'P'는 invoices에서는 대기, refunds에서는 처리 완료 — 컬럼 이름 없이 'P'라고 쓰지 말 것` |
| 조인 키 | `- invoices ↔ invoice_lines는 (invoice_id, revision) 두 키로 조인 — invoice_id만 걸면 개정본 수만큼 행이 곱해진다 → [[invoice-join-keys]]` |
| 금액 합계 | `- 청구 금액 합계에는 voided = false 필수 — 무효 처리된 행이 이중 계상된다` |
| 실행계획 | `- ★★usage_events는 시각 범위 없이 조회 금지(대형). 운영 쿼리는 EXPLAIN 붙인 한 벌만 → [[prod-query-rules]]` |
| 판정 주체 | `- 테이블 생성 주체를 INSERT 문자열 검색으로 판정 금지 — ORM save()를 놓친다 → [[analysis-and-delegation-rules]]` |
| 부작용 | `- ★해지 루틴을 직접 호출하면 좌석 반환 루틴을 이어서 호출해야 한다 — 안 하면 좌석 수가 어긋난다` |
| 데이터 위치 | `- ★★파트너 채널 가입은 subscriptions에 행이 없다(별도 테이블) — 내부 조인하면 그 채널만 결과에서 빠진다` |

템플릿: [`templates/traps-rules.md`](../templates/traps-rules.md)

## 함정을 「필요한 순간」에 다시 띄우기

항상 로드돼 있어도 30줄 중 지금 걸리는 한 줄을 놓친다. 그래서 입력 훅(모드)을 하나 더 뒀다.

- 사용자 입력에 도메인 키워드가 나오면, 함정 파일에서 그 키워드에 걸리는 줄만 골라 문맥으로 붙인다.
- 같은 그룹은 일정 시간 동안 다시 붙이지 않는다(잡음 방지).
- 주간 회고에서 「주입된 세션에서 그 용어로 정정이 또 나왔는가」를 본다. 하루 열 번 넘게 붙는 그룹은 잡음 후보다.

설계: [`mods/term-traps`](../05_hooks-and-scripts/mods/README.md)(원본 구성, 공개판에는 코드 없음)

## 함정이 생기는 경로

1. 사용자가 교정한다 → 그 자리에서 메모리(상세 파일)에 Why와 함께 적는다.
2. 다른 과제에서도 걸릴 함정이면 함정 파일에 한 줄 + 포인터를 추가한다.
3. 같은 유형이 다시 나오면 강조를 올리거나 훅·도구 가드로 올린다.
4. 팀원에게도 유용하면 팀 문서 후보로 올린다.

## 옮긴 뒤 확인할 것

- 서브에이전트가 실제로 rules 파일을 읽는지 다음 위임에서 확인한다(질문 하나를 넣어 본다).
- rules 파일을 고쳤으면 세션을 재시작한다.
- 독립 검증으로 「작업 방식 줄이 섞이지 않았는가」「뒤집힌 옛 규칙이 남지 않았는가」를 본다.

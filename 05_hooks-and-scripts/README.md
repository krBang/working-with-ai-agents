# 훅·스크립트·설정

> **공개판 안내** — 이 폴더에는 코드가 들어 있지 않다. 각 장치가 무엇을 막거나 돕는지, 왜 그렇게 설계했는지만 남겼다. 파일 이름은 원본 구성을 설명하려고 그대로 적었다.

문서 규칙 중 **반드시 지켜져야 하는 것**을 기계로 강제하고, 컨텍스트를 낭비하는 도구 호출을 스크립트로 바꾼 것들의 설계 기록이다.
원본에서 고유 값(경로·서비스 이름·도구 이름)은 전부 설정 파일·환경변수·자리표시자로 빼 두었다.

## 구성

원본 구성(공개판 미포함)이다.

```
hooks/
  guard.mjs                    실행 전(PreToolUse) 가드 — 차단·확인
  guard.config.example.json    가드 설정 예시
  guard_test.py                가드 회귀 테스트(82 사례)
  sql_check.py                 실행 후(PostToolUse) — 문서에 쓴 SQL 블록 자동 점검
  sql_check.config.example.json
  sql_check_test.py            SQL 점검 훅 회귀 테스트(10 사례, DB 접속 없음)
scripts/
  pr_cli.py                    PR 생성·수정·조회·댓글·병합(REST, 응답 한 줄)
  to_codex.py · to_claude.py   두 에이전트 사이의 메시지 전달
  bridge_register.py           메시징 레지스트리(현재 세션 이름·대화 ID) 갱신
  session_metrics.py           세션 기록에서 작업 방식 지표 추출(개편 전후 비교)
  leak_check.py                공개 저장소에 올리기 전 유출 검사
mods/                          입력 훅·화면 띠(플러그인) 5종 → mods/README.md
settings.example.json          권한·훅 구성 예시
```

원본에는 스킬별 스크립트(`check.py`·`branch_tidy.py`·`measure.py`·`set_clip_html.ps1`)도 있었다. 스킬 설명은 [`04_skills/`](../04_skills/README.md)에 있다.

## 1. 가드 훅 — `guard.mjs`

원본 기준의 설계 서술이다.

| 대상 | 판정 | 이유(Why) |
|---|---|---|
| `git add .`·`-A`·`-u`·`*`, `git stage .`, `git commit -a` | **차단** | 여러 과제의 미커밋 변경이 한 클론에 겹쳐 있어 한 번의 실수로 섞인다 |
| `git commit`·`push`(전역 옵션·별칭·`-C` 형태 포함) | **확인** | 밖으로 나가는 상태 변경 |
| 비밀번호·자격증명 파일 읽기(도구·셸 양쪽) | **차단** | 경로를 환경변수로 넘기는 것만 허용한다 |
| 허용한 개발 환경 DB 서비스 외 접속, 운영 DB 별칭·호스트 | **차단** | 명령에 운영 DB 별칭·호스트가 있으면 실행 전에 막는다 |
| 가드 설정·훅 파일 자체의 수정 | **확인** | 가드가 스스로를 끄지 못하게 |
| 메인 워킹트리가 깨끗한데 `git worktree add` | **확인** | 깨끗하면 브랜치 전환이 기본 |
| 읽기 전용으로 둘 MCP 서버의 쓰기 도구 | **차단**(조회만 통과) | 쓰기는 응답이 짧은 전용 스크립트로 보낸다 |
| 발번 도구의 제목·설명이 여러 줄이거나 길다 | **차단** | 「간단하게」라는 규칙이 문구로는 안 지켜졌다 |
| 매 호출 승인 도구(발번·수정 등) | **확인** | 권한 설정과 이중으로 건다 |
| PR 스크립트의 병합 서브커맨드 | **확인** | 되돌리기 어렵다 |

### 설계 메모

- **차단과 확인을 가른다.** 되돌릴 수 없거나 규칙상 금지인 것은 차단(종료 코드 2 + 사유), 사용자가 판단할 것은 확인(승인 창).
- **오탐을 줄이는 두 장치.** ① heredoc·here-string 본문은 데이터로 보고 검사에서 뺀다. ② `echo`·`grep`·`git log` 같은 텍스트 전용 명령은 접속·커밋 검사에서 뺀다. 처음 버전은 문서에 접속 문자열 예시를 쓰는 명령까지 막았다.
- **미탐을 테스트로 메운다.** 독립 검증에서 `git -c … add .`, `git.exe`, `stage`, 따옴표·딕셔너리 형태의 서비스 지정, 환경변수 형태가 빠져나가는 것이 드러났다. 사례를 추가할 때마다 테스트에 넣는다(원본에서 18 → 52 사례로 늘었고, 일반화한 판에서는 82 사례로 다시 썼다).
- **권한 설정과 병행한다.** `permissions.deny/ask`는 정해진 명령 모양만 잡는다. 훅은 모양이 달라도 잡는다. 둘 다 둔다.
- **설정이 없어도 최소 규칙은 돈다.** Git 규칙과 비밀 파일 규칙은 설정 파일 없이 동작하고, DB·MCP 규칙은 설정이 있을 때만 켜진다.
- **훅이 죽으면 통과가 아니라 차단이 되게 한다.** 기본 동작은 훅이 크래시하거나 시간 초과하면 호출을 통과시키는 것이었다. 설정에서 실패 시 차단(`onFailure: block`)으로 바꿨다.
- Windows에서는 훅이 어느 셸로 실행되는지부터 확인한다. 경로 표기(`/c/…` ↔ `C:/…`)를 훅 안에서 변환한다.
- 스크립트를 경유한 쓰기처럼 훅이 **탐지하지 못하는 경로**가 있다. 훅은 실수 방지용이고, 1차 방어는 계정 권한(읽기 전용 계정)이다.


## 2. SQL 점검 훅 — `sql_check.py`

원본에서는 분석 문서(`.md`)에 SQL 코드블록을 쓰면 [`query-plan-check`](../04_skills/query-plan-check/SKILL.md) 스킬의 `check.py`로 자동 점검하게 했다.

- 금지 판정(대형 테이블에 진입 인덱스 없음)이면 종료 코드 2로 에이전트에게 사유를 돌려주도록 설계했다.
- 경고는 문맥 한 줄로 전달한다.
- Edit은 바꾼 블록만 본다(손대지 않은 블록을 다시 경고하지 않는다).
- 점검 도구 자체의 오류로는 작업을 막지 않는다.

**Why** 「운영 쿼리는 인덱스 근거를 대라」는 규칙이 문서에 있었는데도 같은 실수가 세 번 반복됐다. 쿼리를 문서에 쓰는 순간 점검이 돌게 했다.

## 3. PR 스크립트 — `pr_cli.py`

원본 스크립트는 다음처럼 만들었다.

- 생성 시 레포의 기본 리뷰어를 페이지네이션 끝까지 조회해 본인만 빼고 넣는다.
- 출력은 번호·상태·주소·리뷰어 수 한 줄.
- 댓글 목록·답글·해결·승인·병합까지 다뤘다. 병합은 훅이 확인 창을 띄운다.
- 인증 값은 환경변수로만 받고 어디에도 출력하지 않는다.

**Why** PR 조회·생성·수정 MCP의 응답 전문이 호출당 수만 자였고 한 달 도구 출력의 최대 원천이었다. MCP에 없는 기능(병합·댓글 해결)을 MCP로 시도하다 실패를 수십 번 반복한 주도 있었다. 스크립트에 그 기능을 넣고 MCP 쓰기는 훅으로 막았다.

사용 중인 Git 호스팅의 REST API 형식에 맞춰져 있었다. 다른 호스팅이면 경로와 응답 필드를 바꿔야 한다.

## 4. 브리지 스크립트 — `to_codex.py` · `to_claude.py` · `bridge_register.py`

두 종류의 에이전트가 서로에게 메시지를 보낸다. 설계와 규칙은 [브리지 메시징](../07_multi-agent/02_bridge-messaging.md).

## 5. 효과 측정 — `session_metrics.py`

세션 기록(.jsonl)에서 사용자 메시지 100개당 질문 도구 호출·에이전트 호출·AI 정정 발화·사용자 지적 키워드·도구 결과 문자 수를 뽑아 개편 전후·같은 모델·진입점별·월별로 보여 주도록 만들었다. 읽는 법은 [규칙에 대한 규칙 9](../01_principles/05_rules-about-rules.md).

## 6. 유출 검사 — `leak_check.py`

이 플레이북을 공개 저장소로 내보내면서 만든 도구다. 금지어 정규식 파일(저장소 **밖**에 둔다)과 내장 탐지(이메일·주소·IP·홈 경로·긴 숫자열·해시 모양)로 폴더 전체를 훑는다.

이 공개판은 금지어 패턴 검사와 사람 검토를 거쳤다.

## 7. 설정 — `settings.example.json`

| 항목 | 의도 |
|---|---|
| `permissions.deny` | 전체 스테이징, 비밀 파일 읽기 |
| `permissions.ask` | 커밋·푸시, 발번·수정 도구 |
| `permissions.allow` | 읽기 전용 MCP 도구(목록 조회 등) |
| `hooks.PreToolUse` / `PostToolUse` | 가드 훅 / SQL 점검 훅 |
| `attribution` 빈 값 | 커밋·PR 서명 문구 끄기(「서명 금지」 규칙과의 충돌 제거) |
| `env`의 UTF-8 강제 | 스크립트 출력의 인코딩 오류 반복(여러 세션) 제거 |
| `skillOverrides` | 쓰지 않는 스킬을 꺼서 상시 컨텍스트를 줄인다 |
| `spinnerTipsEnabled`·`showTurnDuration` false | 화면 소음 줄이기 |
| `modelSettings.*.effortLevel` | 설계용 모델의 기본 추론 강도를 높게 |
| `extraKnownMarketplaces`(directory) | 로컬 폴더를 플러그인 마켓으로 — 팀 도구와 개인 모드를 플러그인으로 배포 |

원본 설정에는 자동 모드용 환경 서술(신뢰 저장소·보호 브랜치·민감 데이터 위치)도 있었다. 환경 고유 내용이라 옮기지 않았다.

# 모드(입력 훅·화면 띠)

> **공개판 안내** — 이 폴더에는 코드가 들어 있지 않다. 각 장치가 무엇을 막거나 돕는지, 왜 그렇게 설계했는지만 남겼다. 파일 이름은 원본 구성을 설명하려고 그대로 적었다.

에이전트 도구의 플러그인(모드) 기능으로 만든 작은 확장 다섯 개의 설계 기록이다.

| 모드 | 하는 일 | 왜 만들었나 |
|---|---|---|
| `kickoff-skill` | 그날 첫 「업무 시작」 입력에 지정한 스킬의 실행 지시를 붙인다(하루 1회) | 스킬 description만으로는 첫 호출이 보장되지 않았다. 세션 점검이 먼저 돌거나 「이미 했다」고 판단하는 날이 있었다 |
| `term-traps` | 입력에 도메인 키워드가 나오면 함정 파일에서 걸리는 줄만 골라 문맥으로 붙인다(그룹별 재주입 간격 있음) | 함정 파일은 항상 로드되지만 수십 줄 중 지금 걸리는 한 줄을 놓쳤다. 용어·상태값 정정이 2주에 일곱 번 나왔다 |
| `correction-log` | 정정 표현이 든 사용자 입력과 직전 답변 앞부분을 `corrections.jsonl`에 남긴다 | 주간 회고가 큰 세션 로그 전체 대신 이 파일을 1차 원재료로 쓴다 |
| `now-doing` | 입력창 위 5줄 띠 — 지금 하는 일(마지막 안내 문장)·실행 중 도구·이력·턴 요약. 개발 환경 쓰기는 색으로 구분 | 긴 작업 중 「지금 뭘 하고 있나」를 스크롤 없이 보고 싶었다 |
| `status-band` | 입력창 위 한 줄 — 로컬 서버 상태·실행 중 에이전트 수 | 서버를 띄워 둔 채 잊거나 유휴 에이전트를 방치하는 일을 줄이려고. 실제로는 꺼 두고 `now-doing`만 썼다 |


## 이식할 때 환경마다 달라지는 값

원본에서는 각 모드의 등록 파일 맨 위에 환경 고유 값을 상수로 모아 두었다. 공개판에는 코드가 없으므로, 옮길 때 자기 환경에 맞춰 정해야 하는 값만 적는다.

| 모드 | 환경마다 달라지는 값 |
|---|---|
| kickoff-skill | 트리거 문구 정규식, 실행할 스킬 이름, 시간대 |
| term-traps | 키워드 그룹, 함정 파일 경로, 재주입 간격 |
| correction-log | 정정 신호 정규식, 기록 폴더 |
| now-doing | 개발 환경 도구의 MCP 서버 이름과 도구 이름 집합 |
| status-band | 살펴볼 로컬 서버 목록(이름·포트·상태 경로), 메모리 인덱스 경로 |

## 검증 상태

- 원본의 모드 코드는 TypeScript 구문 진단 0건과 변환 결과의 `node --check` 통과, `now-doing`의 순수 함수 단위 검증까지 했다.
- 호스트의 모드 런타임 안에서 일반화한 형태를 실행해 보지는 않았다. 옮길 때는 호스트 버전의 모드 API에 맞는지 확인해야 한다.

## 운영하면서 배운 것

- **모드마다 지표와 판정일을 정한다.** 실행 지시 모드는 「지킨 날/붙은 날」, 용어 모드는 「주입 횟수·그룹 분포·주입 뒤 정정 재발」, 정정 로그는 「실제 정정 비율·오탐 표현 상위」. 2주 뒤 유지·조정·제거를 정한다.
- **하루 열 번 넘게 붙는 문맥은 잡음이다.** 재주입 간격과 키워드를 조정한다.
- **관찰만 한다.** `now-doing`은 도구 호출 훅을 걸지 않고 응답 스트림만 본다. 도구의 백그라운드 전환·실시간 출력에 영향을 주지 않기 위해서다.
- **실패해도 입력을 막지 않는다.** 모든 훅은 예외를 삼키고 원래 흐름을 그대로 넘긴다.
- 다른 에이전트가 일회용 세션으로 메시지를 전달할 때 이 모드들이 같이 로드되면, 그 메시지가 「사용자 정정」으로 기록된다. 전달용 세션은 사용자 설정을 끄고 띄운다. → [브리지 메시징](../../07_multi-agent/02_bridge-messaging.md)

지난 7일 동안의 내 세션 기록을 회고해 「반복되는 실수」를 찾고, 이를 막을 개선 후보를 제안해 주세요. 이어서 지난 7일의 에이전트 도구 신기능·변경점을 확인해 우리 설정과 대조해 주세요. 대화 답변은 존댓말 한국어.

## 입력
- 세션 기록: `<sessions-dir>/*.jsonl` 중 수정 시각이 최근 7일인 파일. 크니까 통째로 읽지 말고 스크립트(`python -P`)로 사용자 메시지·도구 오류만 추려 볼 것. 스크립트는 임시 폴더에 둔다.
- 정정 기록: `<corrections-log>`(입력 훅 correction-log가 남긴 파일) — 정정 표현이 든 사용자 입력과 직전 답변 앞부분. **정정 신호의 1차 원재료**로 쓰고, 세션 기록은 앞뒤 맥락 확인용. 정정 표현이 있어도 직전 행동을 뒤집지 않는 일반 질문(「왜 이렇게 동작해?」)은 정정에서 뺀다.
- 현재 규칙(대조용, 읽기만): `<workspace>/CLAUDE.md`, `<workspace>/.claude/rules/domain-traps.md`, `<memory-dir>/MEMORY.md`와 거기 링크된 피드백 메모리.
- 신기능 대조용 설정(읽기만): `~/.claude/settings.json`, `~/.claude/hooks/`, `<workspace>/.claude/skills/`, `~/.claude/scheduled-tasks/`.

## 찾을 신호
1. 사용자 정정: 「아니」「그거 말고」「다시」「틀렸」「왜 ~했」「하지 말라고」 등으로 시작하거나 직전 행동을 뒤집는 사용자 메시지
2. 가드·권한 차단: 훅 거부, 권한 거절, 같은 명령 재시도
3. 되돌림: 직후 원복한 편집, 철회한 결론
4. 비효율: 같은 파일 반복 읽기, 실패 후 같은 호출 재실행, 쓸모없는 에이전트 위임

## 판정
- 같은 유형이 2회 이상(세션이 달라도) 나온 것만 후보. 1회성은 버린다.
- 이미 규칙에 있는데 또 어긴 것은 「규칙은 있는데 안 지켜짐」으로 따로 표시 — 문구 추가가 아니라 강제 수단(훅·스크립트·스킬 단계)이 필요한지 판단한다.
- 강제 수준은 높은 쪽부터 검토: 훅/스크립트 차단 > 스킬 절차 단계 > 규칙 문구.

## 에이전트 도구 신기능 확인
1. 설치 버전을 확인한다(실패하면 「미확인」).
2. 공식 변경 내역에서 실행일 기준 지난 7일 릴리스만 고른다. 날짜가 확인된 항목만 쓰고 지어내지 말 것. 7일 안에 새 릴리스가 없으면 「신규 릴리스 없음」.
3. 각 변경을 우리 설정과 대조해 셋 중 하나로 분류한다.
   - **영향 있음**: 우리 훅·권한·스킬·예약 작업의 동작이 바뀌는 것. 영향받는 파일 경로를 적는다.
   - **써 볼 만함**: 위 「반복 패턴」이나 우리 업무(<우리 스택>)에 바로 쓸 수 있는 것.
   - 그 외는 버린다(표에 넣지 않음).
4. 반복 패턴의 개선 후보를 신기능으로 더 싸게 해결할 수 있으면 그 방법을 개선 후보에 적는다.

## 입력 훅(모드) 점검
세션 기록에서 각 모드가 붙인 문맥 머리말로 센다(코드 추가 없이).
1. 실행 지시 모드 — 지시가 붙은 날마다, 그 뒤 첫 도구 호출이 지정 스킬이었는지(지킨 날/붙은 날).
2. 용어 함정 모드 — 주입 횟수와 그룹 분포. 주입된 같은 세션에서 그 용어로 정정이 나왔는지. 하루 10회 넘게 붙는 그룹은 「잡음 후보」.
3. 정정 기록 모드 — 기록 건수, 그중 실제 정정 비율, 오탐 표현 상위 3개(키워드 조정용).
표 한 개로: 모드 / 지표 / 이번 주 값 / 판정(유지·조정·제거 후보) / 조정안 1줄.

## 규칙 감량 후보
<!-- 이 절은 「규칙이 늘어나는 비용은 에이전트가 관리한다」를 정한 날 넣은 초안이다. 실행 실적이 없으니 첫 몇 주는 결과를 보고 기준을 조정한다. -->
현재 규칙(위 대조용 파일)에서 아래 둘을 찾는다. 이 절만 세션 기록의 범위를 최근 28일로 넓히고, 스크립트로 규칙의 핵심어만 센다.
1. 4주 넘게 쓰이지 않은 규칙 — 지난 4주의 세션 기록·정정 기록·일일노트에 그 규칙이 적용되거나 인용된 흔적이 없는 줄. 흔적이 없다는 것은 「필요 없다」의 증거가 아니므로 후보로만 올린다.
2. 서로 겹치는 규칙 — 같은 주제를 두 곳 이상에서 말하는 줄(규칙 파일 ↔ 메모리, 묶음 ↔ 묶음).
표 한 개로(최대 5행): 규칙(파일·줄) / 유형(미사용·중복) / 근거 1줄 / 제안(삭제·합치기·그대로).

## 출력
파일 하나만 만든다: `<docs-vault>/_docs/개인/작업방식_개선/주간회고/주간회고_<YYYYMMDD>.md`(폴더가 없으면 생성, 날짜 = 실행일).
프론트매터:
```
---
owner: <owner>
last_reviewed: <YYYY-MM-DD>
status: 기록
category: 작업방식개선
tags: [주간회고]
---
```
본문(화면 1.5쪽 이내):
1. 한 줄 요약(세션 수·정정 건수·차단 건수·설치 버전)
2. 반복 패턴 표: 패턴 / 횟수 / 대표 사례 1줄(세션 파일명·날짜) / 기존 규칙 여부
3. 개선 후보 1~3건: 무엇을 / 어디에(훅·스킬·규칙 파일 경로) / 강제 수준 / 기대 효과
4. 반복 패턴이 없으면 「이번 주 반복 실수 없음」이라고 쓰고 5로 넘어간다.
5. 신기능 표(최대 5행): 버전·날짜 / 변경 / 분류 / 우리 쪽 해당 파일·첫 시도 1줄 / 출처. 해당 없으면 한 줄로.
6. 모드 점검 표.
7. 규칙 감량 후보 표(해당 없으면 한 줄로).

## 금지
- 규칙·메모리·훅·스킬·설정 파일을 직접 고치지 말 것(제안만). 도구 업데이트·설정 변경 실행 금지. git 커밋·푸시 금지.
- 고객 개인정보·실제 식별 번호·비밀번호·토큰을 사례에 옮기지 말 것 — 식별 번호는 `***`로 가린다.
- 위 출력 파일 외에 워크스페이스에 파일을 만들지 말 것.

마지막 답변은 만든 파일 경로, 개선 후보 제목 1~3줄, 「영향 있음」 신기능 제목(있을 때만)만.

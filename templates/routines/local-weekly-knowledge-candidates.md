이번 주(월~오늘) 내 업무 기록에서 **팀 공유 문서에 남길 만한 정보·업무 처리 방식**을 골라 후보 목록과 초안을 만들어 주세요. 대화 답변은 존댓말 한국어.

## 입력(읽기만)
- 일일노트: `<docs-vault>/_docs/일일노트/YYYY-MM-DD.md` 중 이번 주 날짜(월초면 지난달 폴더도). 「확인한 것」「실행·실측」「미결·다음」「받은 것」 절 위주.
- 메모리: `<memory-dir>/` 중 이번 주 수정된 과제 파일, `MEMORY.md` 활성·종결 줄.
- 팀 문서 규칙·템플릿: `<docs-vault>/AGENTS.md`(문서 작성 규칙), `<docs-vault>/_templates/`.
- 기존 팀 문서(중복 확인): `<docs-vault>` 아래 개인 작업장(`_docs`)을 **제외한** 폴더. 원격 조회·브랜치 전환을 하지 말고 지금 작업 트리 파일을 검색한다.

## 고르는 기준
팀 문서는 팀원이 읽고 따라 하는 **정보·업무 처리 방식 공유**용이다.
- 넣는 것: 운영 절차(재처리·데이터 보정·배포/반영 순서·장애 대응), 도메인 지식(코드값 의미·테이블 관계·판정 기준·흔한 함정), 확정된 정책·결정과 그 근거, 원인이 밝혀진 장애·결함의 원인과 대응
- 빼는 것: 개인 작업 방식(에이전트·자동화 설정·일일노트 운영), 아직 확정되지 않은 분석·미결, 일회성 데이터 추출, 이미 팀 문서에 같은 내용이 있는 것

## 중복 확인
후보마다 핵심어 2~3개(객체 이름·코드값·업무 용어)로 기존 팀 문서 폴더를 검색한다.
- 같은 주제 문서가 있으면 「갱신 후보」 + 그 문서 경로와 덧붙일 내용 요지
- 없으면 「신규 후보」 + 들어갈 폴더(팀 문서 규칙의 폴더 표 기준: 절차 / 일회성 작업 기록·사후 분석 / 규칙 / 과제 설계·현황 / 장애 대응)
- **검색 0건은 「없음」의 증거가 아니다** — 다른 이름으로 있을 수 있으니 폴더 목록·파일명도 훑고, 판단이 애매하면 「중복 미확인」으로 표시한다.
- 지난 후보 파일(이 폴더)도 읽는다. 이미 PR로 올린 후보는 빼고, 「운영 반영 후」처럼 조건부로 남긴 후보는 이번 주에 조건이 풀렸을 때만 다시 올린다.

## 출력(이 폴더에만 쓴다)
`<docs-vault>/_docs/개인/팀문서후보/`(없으면 생성)
1. `후보_<YYYYMMDD>.md` — 프론트매터:
```
---
owner: <owner>
last_reviewed: <YYYY-MM-DD>
status: 기록
category: 팀문서후보
tags: [팀문서후보]
---
```
   본문(화면 1쪽 이내): 표 = 후보 / 신규·갱신(기존 경로) / 폴더 / 근거(일일노트 날짜·메모리 파일) / 팀에 공유할 이유 1줄. 후보가 없으면 「이번 주 반영 후보 없음」 한 줄.
2. 상위 최대 3건만 초안: `초안_<YYYYMMDD>_<주제>.md` — 해당 분류의 팀 템플릿 형식과 문서 작성 규칙(표 우선·프론트매터)을 따른다. 갱신 후보는 「기존 문서 어느 절에 무엇을 덧붙일지」만 쓴다. 상태는 초안.

## 금지
- 팀 문서 본체(개인 작업장 밖) 파일 수정·생성, 스테이징·커밋·푸시·브랜치·PR 생성 금지. 반영은 사용자가 고른 뒤 다른 세션에서 한다.
- 고객 개인정보(이름·연락처·주소·회원 식별값)·실제 식별 번호·비밀값을 초안에 옮기지 말 것 — 예시가 필요하면 자리표시자 형태로 가린다.
- 메모리·일일노트·규칙 파일 수정 금지.

마지막 답변은 만든 파일 경로와 후보 제목 목록만.

# 위임 프롬프트 템플릿

위임받은 에이전트는 메인의 대화도 메모리도 보지 못한다. 이 프롬프트가 유일한 맥락이다.

## A. 구현 위임

```
## 목표
<무엇을 왜 바꾸는가 — 한두 문장>

## 이미 확인·배제한 것
- <읽어 본 위치와 결론>
- <하지 않기로 한 접근과 이유>

## 대상과 변경 내용
- `<파일 경로 1>`: <어디에 무엇을 어떻게>
- `<파일 경로 2>`: <…>

## 지킬 것
- <프로젝트 코드 관례 — 메모리의 코드 스타일 묶음에서 그대로>
- 파일 헤더의 변경 이력 줄을 추가하지 않는다.
- 범위 밖 파일을 고치지 않는다. git 커밋·푸시를 하지 않는다.
- 작업 폴더: `<worktree 경로>` — 다른 폴더(<상대가 쓰는 폴더>)는 건드리지 않는다.
- 먼저 `<workspace>/.claude/rules/<domain>-traps.md`를 읽는다.

## 검증(통과해야 완료)
- `<컴파일 명령>` 종료 코드 0
- (설정·매퍼 파일을 바꿨으면) 로컬 서버 기동 + `<API 호출>` 응답 확인
- <관련 테스트 명령>

## 완료 보고 형식
- 바꾼 파일과 요지(파일별 한 줄)
- 검증 명령과 결과
- 새로 만든 식별자 목록(약어 기준 확인용)
- 못 한 것·확인하지 못한 것
```

## B. 분석·설계 위임 (추론 강도를 높게 지정)

```
## 질문
<답해야 할 질문 하나 — 「이 변경이 X 경로에 영향을 주는가」처럼 판정 가능한 형태>

## 자료
- <파일·문서 경로> (읽기만)
- 검색 키: <테이블·구분 조건·코드 enum>

## 범위
- 볼 영역: <프로시저 / 배치·컨슈머 / API·화면 중 어디>
- 보지 않을 것: <…>

## 답의 형식
- 항목별 판정 + 근거 `파일:줄`. 「영향 없음」도 근거를 단다.
- 읽지 못한 것은 「미확인」으로 적는다. 검색 0건을 「없음」의 근거로 쓰지 않는다.
- 추정은 「추정」이라고 표시한다.
```

## C. 독립 검토 위임 (내 결론을 주지 않는다)

```
아래 자료만 보고 빠진 것을 찾아 주세요. 내 판단은 일부러 적지 않았습니다.

- 검토 대상: <TC 표 / 설계 문서 / diff 경로>
- 찾을 것: <빠진 채널·경로·판정 기준 / 가드 우회 / 회귀>
- 형식: 지적마다 심각도 · `파일:줄` · 문제 · 재현 방법
- 범위 밖·의도된 제약은 감점하지 않는다(근거: <README·설계 문서>)
- 상태를 바꾸는 호출은 하지 않는다
```

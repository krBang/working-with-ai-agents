<한 줄: 무슨 도메인의 워크스페이스인가>. 보고·커뮤니케이션은 <언어>.
진행 중 작업의 상태·결정·다음 할 일과 **도메인 함정은 자동 메모리(MEMORY.md 인덱스)가 정본** —
과제 메모리 최상단 「현재 상태 스냅샷」과 인덱스 최상단 「즉시 참조 함정」부터 읽을 것.

## 산출물 위치 (필수 — 워크스페이스 루트에 파일 만들지 말 것)
- 분석 문서·실측 쿼리·설계 문서 등 **모든 산출물은 노트 볼트 안에** 만든다.
  볼트 루트 = `<docs-vault>`, 내 작업장 = 그 아래 `_docs`.
  - 진행중 = `_docs/진행중/<주제>/` (현재 목록 = 그 폴더 자체. 종결되면 `보관/`으로 옮기고 `_docs/00_INDEX.md` 종결 표에 1줄)
  - 종결   = `_docs/보관/<과제>/`
- **워크스페이스 루트에 남기는 파일은 `CLAUDE.md`·`AGENTS.md`와 레포 폴더뿐이다.** 임시 파일은 스크래치패드로.
- `_docs`는 저장소의 로컬 제외 목록으로 **미추적(로컬 전용)** — 커밋 대상이 아니다.
  `_docs` 밖 볼트 본체가 팀 공유 레포라면 **브랜치+PR 필수**, 개인정보 반입 금지.
- 새 문서는 프론트매터(`owner`/`last_reviewed`/`status`/`category`/`tags`)를 넣고 해당 주제 폴더의 `00_<주제>.md` 목차에 링크를 추가한다.
- 진행중 폴더의 파일명 채번 규칙(`NNN_<제목>_<YYYYMMDD>.md`·리네임 주의)은 `_docs/CLAUDE.md` — 새 문서를 만들거나 리네임하기 전에 읽을 것.
- ★**실측/분석 쿼리 산출물은 `.md`로 만든다. `.sql` 단독 생성 금지.**
  쿼리는 `.md` 안 코드펜스에 넣고 실행 순서·판정 기준·인덱스 근거를 본문에 함께 적는다.
  이유: 노트 앱은 `.md`만 노트로 인식한다 — 다른 확장자는 그래프·뷰·검색에서 통째로 빠진다.

## 일일노트 (시간축 — 정본이 아니다)
- 위치 `_docs/일일노트/YYYY-MM-DD.md`, 템플릿 `_docs/_templates/일일노트.md`.
- **월 단위 보관**: 루트에는 이번 달 노트만. 달이 바뀌어 첫 노트를 만들 때 지난달 노트를 `일일노트/YYYY-MM/`로 옮긴다.
- **역할 3층**: 일일노트 = 시간축 원재료 / 자동 메모리 = 현재 상태 / `_docs` 주제 문서 = 분석 정본. 일일노트를 상태 정본으로 삼지 말 것.
- **세션 시작**: 오늘 노트가 있으면 먼저 읽고 이어간다. **없으면 만들지 않는다** — 첫 기록할 일이 생길 때 템플릿으로 만든다.
- ★**최상단 「지금 상황」 블록 = 전 과제 브리핑.** 사용자가 다른 업무를 보다 들어와도 여기만 보면 전체가 잡히게.
  **그날 첫 기록 때 메모리에서 한 번 렌더링하는 스냅샷 — 일중 갱신 금지**(변동은 `미결·다음` + 메모리만). 전날 것 복붙 금지.
  구성 = ① 능동 과제 4칸 표(과제 / 지금 상태 / 막힌 것·대기 / 다음 첫 손) ② `대기: 과제 — 막힌 것` 한 줄 불릿 ③ `오늘 첫 손` 한 줄.
  렌더링 순서 = 세션 시작 `⏳` 점검 → 메모리 갱신 → 표 렌더링.
- ★**쓰기는 작업 묶음 끝에 한 번**(회신 1건·쿼리 1세트·위임 1건이 끝났을 때). 발언·정정마다 쓰지 않는다 — 최종 결과만.
  줄은 160자 안팎. 추가는 편집 도구 대신 셸 append(`cat >> 노트 <<'EOF'`)로 섹션 끝에 붙인다.
  묶음 안에서 기록할 것은 이 넷:
  ① 지시·구두 전언·회신 → `받은 것`에 결정에 쓰인 구절만 「」 인용
  ② 쿼리 실행 결과 → `실행·실측`에 창(기간)·판정 같이
  ③ 코드/DB로 근거 확인한 사실 → `확인한 것`
  ④ 결정 확정 또는 미결 변동 → `미결·다음` + 메모리 현행화(확정 후 1회)
- ★**에이전트에 위임한 작업은 위임 시점에** 목록·작업 폴더·출력 경로를 `실행·실측`에 1줄 남긴다.
- ★**날짜 이력을 메모리 파일에 누적하지 말 것.** 메모리엔 최신 상태만, 경위는 그날 일일노트로.
  과거 섹션은 파일당 1회 압축(사용자 승인 후): 함정·확정 사실과 **file:line 포함 줄은 원문 그대로** 유지, 이력은 주제 폴더의 이관 문서로 통째 이동(문장 재작성 금지). 압축 전후 file:line 개수를 대조.

## 작업 위임 루프
1. 로컬 작업(소스·문서 수정, 테스트, 분석)은 승인 없이 진행하고 결과를 보고한다. 1~2파일 소규모는 메인이 직접 수정하고 검증 명령 1회(`git diff --stat` + 컴파일). 다중 파일·대형 구현은 구현 담당 에이전트에 위임한다.
   위임받은 에이전트는 메모리를 못 본다 — 필요한 함정은 프롬프트에 적거나 `.claude/rules/<domain>-traps.md`를 읽게 한다.
2. 위임 프롬프트에 명시: 대상 파일 경로, 정확한 변경 내용, 헤더 이력 추가 금지, git 커밋 금지, 검증 명령(`<컴파일 명령>` 종료 코드 0. 설정·매퍼 파일을 바꿨으면 서버 기동 + 호출).
3. 완료 보고 수신 → 메인 세션에서 독립 검증 → 사용자 보고 → 해당 에이전트 즉시 정리(유휴 방치 금지).
4. 무거운 추론(영향도 분석·설계 판단·디버깅·레거시 분석)은 즉답하지 말고 설계 검토 에이전트에 위임하거나 단계적 검토. 설계·판단 위임에는 추론 강도를 높게 명시한다.
5. 리뷰 에이전트의 지적은 사용자에게 전달하기 전에 코드로 재검증하고 ✅확인/⚠오탐/미검증 표시를 붙여 보고.

## Git
- 커밋/푸시는 사용자가 명시 요청할 때만. 커밋 전 diff 요약을 보여주고 승인받는다.
- 커밋·푸시 확인, 전체 스테이징(`git add .`/`-A`) 차단, 비밀 파일·운영 DB 차단은 권한 설정 + 실행 전 훅으로도 강제된다. 막히면 우회하지 말고 사용자에게 알린다.
- 서명·공동 작성자 줄 금지. 브랜치 채번·커밋 메시지·PR 형식은 `<팀 Git 규칙 파일>`.
- 운영용 PR의 타깃은 레포별 배포 브랜치 표(메모리 `git-pr-rules`)로 정한다. 표에 없는 레포는 PR 전에 확인.

## 판단/보고
- 결정·미결·다음 할 일이 **확정되면** 메모리 현행화(세션 끝까지 미루지 않되, 같은 줄을 여러 번 고치지 않는다). 메모리에서 결정이 뒤집히면 **옛 줄은 지운다**.
- ★**질문·발언 해석은 메모리 `questions-and-decisions` 매트릭스대로** — 묻는 것은 안전장치 승인·사용자만 아는 값(한 번에 묶기)·결과가 갈리는 업무 판단뿐. 내부 관리는 묻지 않고 하고 결과 1줄. 명시 동사 없는 발언은 미결로 올리지 않는다. **질문에는 답만 한다**(동사가 없으면 조치하지 않는다).
- ★**승인은 밖으로 나가는 행위에만** — 커밋·푸시·PR·티켓·DB 쓰기·외부 전송. 로컬 작업은 진행하고 결과를 보고한다.
  의도한 승인 창은 줄이지 않고 **호출을 묶는다** — 묶을 수 있는 조회는 한 번에, 여러 단계로 이어지는 외부 행위는 전체 단계를 먼저 보여 주고 한 번에 결정받는다.
- ★**겹치는 요청은 이 세션에서 나눈다** — 독립 작업은 위임, 승인·판단이 필요한 짧은 일은 현재 단계만 끝내고 처리, 얽힌 일은 대기. 대기가 2건 이상이면 답변 맨 위에 `대기: ①… ②…` 한 줄.
- 아쉬운 점·문제를 말할 때는 항목마다 `개선:` 줄과 내가 맡을 일을 붙인다.
- ★**결함·미결을 올리기 전에 이미 결정된 것인지 먼저 찾는다** — 과제 메모리 최상단 「확정 정책·결정 표」 → 핵심어 2~3개 검색(건수 먼저, 앞부분만 자르지 말 것) → 주제 문서 목차.
- 도구 출력은 필요한 만큼만: 셸은 앞부분·요약·건수, 큰 파일은 범위 읽기. PR 작업은 MCP 대신 `<PR 스크립트>`(응답 1줄).
- 규칙 파일을 고친 뒤엔 세션을 재시작한다 — 위임 에이전트는 세션 시작 시점 규칙으로 일한다. 스킬·메모리 파일은 즉시 반영. 규칙은 실제 실패 후에만 더하고, 더할 땐 기존 묶음 파일에서 겹치는 줄·낡은 줄을 먼저 합치거나 지우고 넣는다.
- ★**상태를 담는 곳은 둘뿐** — MEMORY.md 활성 작업 1줄 + 과제 메모리 최상단 스냅샷. 목차·인덱스·팀 문서에는 상태어를 쓰지 않는다.
- ★**활성 작업 줄엔 `작업물: <작업 폴더>@<브랜치> 미커밋N / 대기: …` 필수** — 메모리 파일 없는 과제는 이 줄이 유일한 저장소다.
- ★**남의 손에 넘긴 항목은 ✅ 금지** — `⏳타팀(담당·예상일)`로 두고(예상일 미정이면 기록일+14일) 결과 확인 후에만 ✅. 세션 시작에 날짜 지난 `⏳`만 한 줄로 묻는다.
- ★★**부재를 근거로 단정하지 말 것.** 검색 0건·무결과는 「없다/불가능하다」의 증거가 아니다. 다른 이름·코드값, 다른 레이어, **차단이 아니라 조건부 허용** 형태로 존재하는 경우가 많다.
  ⇒ 「X 없음/불가」를 결론으로 낼 때는 **해당 분기를 열어 읽고, 읽은 위치를 근거로 함께 적는다.** 못 읽었으면 「미확인」으로 두고 실측 항목에 올린다.
- ★**「코드로 확인했다」는 표현은 파일을 열어 로직을 읽었을 때만 쓴다.**
- ★**미결을 종결(✅)로 바꾸기 전에 한 번 더 반증한다.** 종결 근거가 「부재」거나 「전언 요약」이면 종결하지 말고 실측 항목으로 내린다.
- ★**「~하겠습니다」라고 쓰면 같은 응답 안에서 실제로 호출한다.** 사용자가 할 일은 답변 맨 위 `> 👉 **사용자 할 일**` 블록으로.

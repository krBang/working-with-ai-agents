# 산출물 위치와 문서 채번

## 1. 모든 산출물은 한 볼트 안에

**규칙** 분석 문서·실측 쿼리·설계 문서는 전부 하나의 노트 볼트 안에 만든다. 워크스페이스 루트에는 규칙 파일(`CLAUDE.md`·`AGENTS.md`)과 레포 폴더만 둔다. 임시 파일은 스크래치패드로 보낸다.

```
<workspace>/
  CLAUDE.md, AGENTS.md          ← 규칙 파일만
  <repo-a>/, <repo-b>/ …        ← 코드 레포
  <docs-vault>/                 ← 노트 볼트(팀 공유 문서 레포일 수 있다)
    _docs/                      ← 개인 작업장(미추적)
      00_INDEX.md               ← 최상위 목차
      진행중/<주제>/             ← 현재 과제. 폴더 목록이 곧 진행 중 목록이다
        00_<주제>.md            ← 주제 목차(MOC)
        001_<제목>_<YYYYMMDD>.md
      보관/<과제>/               ← 종결 과제(통째로 옮긴다)
      일일노트/YYYY-MM-DD.md     ← 이번 달만. 지난달은 YYYY-MM/ 폴더
      _templates/
      개인/                      ← 회고·작업 방식 개선·후보 초안
```

**Why** 분석 파일이 워크스페이스 루트와 여러 폴더에 흩어져 있었다. 한 볼트로 모으니 검색·백링크·뷰가 하나로 묶이고, 「어디 있는지」를 기억할 필요가 없어졌다.

## 2. 산출물은 항상 `.md`

**규칙** 쿼리·로그·표도 `.md` 안 코드펜스에 넣는다. `.sql`·`.txt` 단독 파일을 만들지 않는다. 쿼리 문서에는 실행 순서·판정 기준·인덱스 근거를 본문에 함께 적는다. DB 클라이언트 붙여넣기용 파일이 꼭 필요하면 `.md`를 먼저 만들고 부속으로 둔다.

**Why** 노트 앱은 `.md`만 노트로 인식한다. 다른 확장자는 볼트 안에 있어도 파일 트리·그래프·검색·프론트매터 뷰에서 통째로 빠진다. 경로를 알려 줘도 사용자의 화면에는 보이지 않는다.

## 3. 프론트매터와 목차 등재

새 문서에는 프론트매터를 넣고, 해당 주제 폴더의 목차 문서에 링크를 추가한다.

```yaml
---
owner: "<이름>"
last_reviewed: "YYYY-MM-DD"
status: 진행중        # 문서의 생명주기 상태(초안/진행중/기록/보관)
category: 분석        # 분석 | 설계 | 실측 | 결정 | 일일노트 | …
tags: [주제어1, 주제어2]
---
```

- 등재하지 않으면 고아 문서가 된다.
- 상호 참조는 파일명 문자열이 아니라 노트 앱의 내부 링크로 건다.
- 일일노트는 `status`·`category`를 고정값으로 둬서 진행 중 문서 뷰에 섞이지 않게 한다.

## 4. 진행 중 폴더의 파일명 채번

**형식** `NNN_<제목>_<YYYYMMDD>.md` — 앞 세 자리 번호가 정렬 축이다.

| 규칙 | 설명 |
|---|---|
| 번호는 작성일 순 | 새 문서는 그 폴더의 **끝번호 + 1**. 재번호는 하지 않는다 |
| 사이에 끼울 때만 `005-1_` | `005_` < `005-1_` < `006_` 순으로 정렬된다 |
| 주제 접두를 반복하지 않는다 | 폴더명이 이미 주제다 |
| 날짜 접미는 문서에 적힌 작성일 | 파일 생성 시각과 달라도 접미가 정본이다 |
| 목차 문서(`00_<주제>.md`)는 채번 대상이 아니다 | |

**리네임 주의** 기존 파일 이름을 바꿀 때는 내부 링크, 캔버스 파일 안의 경로, 메모리, 규칙 파일을 함께 고친다. 옛 이름이 새 이름의 부분 문자열이면 치환을 두 번 돌릴 때 접두가 누적되니(`009_009_`), 치환은 **한 번만** 실행하고 끝난 뒤 중복 접두 잔존을 검색으로 확인한다.

**Why** 번호가 없을 때는 문서가 이름순으로 섞여 「어느 것이 최신 정리인가」를 알 수 없었다. 진입점을 「최종 정리」 문서 하나로 두고 번호로 순서를 고정했다.

## 5. 문서에는 상태어를 쓰지 않는다

**규칙** 목차 문서·최상위 인덱스·팀 문서에는 상태어(OPEN/대기/머지)를 쓰지 않는다. 링크·제목·한 줄 설명만 둔다. 상태는 메모리 인덱스 한 줄과 과제 메모리 스냅샷에만 둔다.

**Why** 상태가 여러 문서에 적혀 있으면 하나만 갱신되고 나머지는 거짓이 된다. 실제로 인덱스 문서의 상태 열이 몇 주 전 내용에 멈춰 있었다.

## 6. 추적 범위와 개인정보

| 영역 | 처리 |
|---|---|
| 개인 작업장(`_docs`) | 저장소의 로컬 제외 목록(`.git/info/exclude`)으로 미추적. 커밋 대상이 아니다 |
| 팀 공유 문서 레포 본체 | 브랜치 + PR 필수. 개인정보·실제 식별값 반입 금지 |
| 일회성 추출(개인정보 포함) | 개인 작업장에만 두고 문서 머리에 경고 표시. 종결 뒤 먼저 언급하지 않는다 |

팀 문서로 옮길 초안에는 실제 식별값을 가린 형태로만 예시를 쓴다.

## 7. 종결 처리

1. 주제 폴더를 `보관/`으로 통째 옮긴다.
2. 최상위 인덱스의 종결 표에 한 줄(링크 + 한 구절)을 추가한다.
3. 메모리 인덱스의 활성 작업 줄을 지우고 종결 목록 파일에 한 줄을 넣는다. 재문의나 같은 함정이 다시 나올 때만 연다.
4. 재검색 가치가 있는 지식(원인·대응·함정)은 팀 문서 후보로 올린다.

## 8. 시각 자료의 수치는 계산으로

노트 앱의 캔버스처럼 노드 크기를 숫자로 적어야 하는 형식은 눈대중으로 넣지 않는다. 텍스트 줄 수로 높이를 계산하는 스크립트를 두고, 만들거나 고친 뒤 반드시 돌린다.

**Why** 높이가 모자라면 텍스트가 잘려 카드 절반이 보이지 않는다. 앱이 자동으로 늘려 주지 않는다. 같은 지적을 두 번 연속 받았다.

# 세션 시작과 마무리

세션은 교대 근무다. 앞 세션이 남긴 상태를 정해진 순서로 읽고, 끝날 때 다음 세션이 읽을 것을 정해진 곳에 남긴다.

## 1. 세션 시작

| 순서 | 할 일 | 이유(Why) |
|---|---|---|
| 1 | 메모리 인덱스(자동 로드)의 「활성 작업」 줄과 「즉시 참조 함정」 포인터를 본다 | 인덱스 한 줄이 과제의 현재 상태·작업물 위치·대기 사유를 담는다 |
| 2 | 손댈 과제의 메모리 파일 **최상단 스냅샷**과 「확정 정책·결정 표」부터 읽는다 | 파일이 길어도 위쪽만 읽으면 현재 상태가 잡히게 유지한다 |
| 3 | 오늘 일일노트가 있으면 읽고 이어간다. **없으면 만들지 않는다** | 빈 노트를 양산하지 않는다. 첫 기록할 일이 생길 때 템플릿으로 만든다 |
| 4 | 날짜가 지난 `⏳` 항목만 사용자에게 한 줄로 묻는다 | 남의 손에 넘어간 일은 확인하지 않으면 영영 「대기」로 남는다 |
| 5 | 월초라면 어제 노트는 지난달 폴더에서 찾는다 | 노트는 월 단위로 보관 폴더에 옮긴다 |

그날 첫 기록을 남길 때의 순서: **`⏳` 점검 → 메모리 갱신 → 일일노트 「지금 상황」 블록 렌더링**. 이 블록은 그날 한 번만 렌더링하고 일중에는 고치지 않는다.

### 그날 첫 「업무 시작」

사용자가 「업무 시작」이라고 하면 다른 점검보다 먼저 `daily-standup` 스킬을 실행한다. 스킬 안에서 다음이 순서대로 돈다.

1. 메모리 정리(`memory-tidy`) — 묻지 않고 하고 결과 한 줄
2. 전일/금일 업무 보고 목록 작성
3. 달력 조건이 맞으면 덧붙는 일
   - 그 주 첫 근무일: [주간 개선 점검](08_weekly-improvement-loop.md)
   - 그달 첫 근무일: 머지된 브랜치·worktree 정리 후보 표(읽기 전용 스크립트)

스킬 description만으로는 첫 호출이 보장되지 않아, 입력 훅(모드)이 그날 첫 「업무 시작」에 실행 지시를 붙인다. → [모드](../05_hooks-and-scripts/mods/README.md)

## 2. 작업 묶음이 끝날 때마다

작업 묶음 = 회신 1건, 쿼리 1세트, 위임 1건처럼 하나로 끝나는 단위.

- 일일노트에 **한 번** append한다(받은 것 / 실행·실측 / 확인한 것 / 미결·다음 중 해당하는 절). → [일일노트 3층 구조](03_daily-note-3-layer.md)
- 결정·미결·다음 할 일이 **확정됐으면** 메모리를 한 번 현행화한다. 같은 줄을 여러 번 고치지 않는다.
- 결정이 뒤집혔으면 메모리의 옛 줄을 지운다.
- 에이전트에 위임했으면 **위임 시점에** 일일노트에 한 줄 남긴다(과제·작업 폴더·출력 경로).

## 3. 세션 마무리

| 할 일 | 이유(Why) |
|---|---|
| 건드린 레포마다 `git status --short`로 미커밋 상태를 확인하고 보고한다 | 다른 과제의 변경이 섞여 있지 않은지, 무엇이 아직 로컬에만 있는지 남긴다 |
| 메모리 인덱스 활성 작업 줄에 `작업물: <작업 폴더>@<브랜치> 미커밋N / 대기: …`를 갱신한다 | 메모리 파일이 없는 과제는 이 줄이 유일한 저장소다 |
| 검증이 끝난 위임 에이전트를 정리한다 | 유휴 에이전트를 방치하지 않는다 |
| 띄운 로컬 서버를 끈다(빌드 도구 프로세스뿐 아니라 포트를 잡고 있는 프로세스까지) | 빌드 태스크만 멈추면 서버 프로세스가 포트에 남는다 |
| 승인이 필요한 항목(커밋·PR·외부 전송)을 모아 한 번에 보고한다 | 사용자가 돌아와 한 번에 결정할 수 있게 한다 |
| 필요하면 일일노트 「미결·다음」에 내일 첫 손을 한 줄 남긴다 | 다음 날 업무 보고의 「금일」 재료가 된다 |

## 4. 컨텍스트 압축·재개 뒤

압축이나 세션 재개 뒤에는 상태를 기억에 의존하지 않는다.

- 현재 폴더와 브랜치를 다시 확인한다(잘못된 브랜치에서 이어 가는 사고 방지).
- 과제 메모리 스냅샷과 오늘 일일노트를 다시 읽는다.
- 규칙 파일을 방금 고쳤다면 세션을 재시작한다(위임 에이전트는 세션 시작 시점 규칙으로 일한다).

## 5. 상태가 사는 곳 — 요약

| 무엇 | 어디에 |
|---|---|
| 과제의 현재 상태 한 줄 | 메모리 인덱스 「활성 작업」 |
| 과제의 상세 현재 상태·결정 표 | 과제 메모리 파일 최상단 스냅샷 |
| 경위·날짜 이력·원재료 | 그날 일일노트 |
| 분석·설계·쿼리 정본 | 주제 폴더 문서 |
| 반드시 지킬 도메인 함정 | 프로젝트 rules 파일(항상 로드) |

문서 목차·인덱스·팀 위키에는 상태어(OPEN/대기/머지)를 쓰지 않는다. → [메모리 설계](../03_memory-system/01_design.md)

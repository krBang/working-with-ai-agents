# 예약 루틴

사람이 시키지 않아도 정해진 시각에 도는 에이전트 작업. 두 종류를 쓴다.

| 종류 | 실행 위치 | 등록 위치 | 특징 |
|---|---|---|---|
| A. 클라우드 루틴 | 원격 실행(계정에 묶임) | 서비스의 루틴 목록 | PC가 꺼져 있어도 돈다. 로컬 파일을 못 본다 → **웹 조사 전용** |
| B. 로컬 예약 작업 | 내 PC의 데스크톱 앱(앱이 켜져 있어야 실행) | `~/.claude/scheduled-tasks/<id>/SKILL.md` | 로컬 세션 기록·메모리·노트를 읽을 수 있다 → **회고·후보 추출** |

프롬프트 템플릿은 [`templates/routines/`](../templates/routines/README.md)에 있다.

## 운영한 루틴

### A. 클라우드 루틴(활성 2 · 1회성 3)

공통 조건: 중간급 모델, 도구는 웹 검색·웹 읽기·셸·파일 읽기만, MCP 연결 없음, **웹 조사 → 최종 답변만**(파일·PR 금지), 「날짜·출처가 확인된 것만, 지어내지 말 것」, 화면 2쪽 이내, 첫 단계에서 `date -u`로 조사 창을 계산.

| 루틴 | 주기 | 하는 일 | 출력 형식 |
|---|---|---|---|
| 주간 AI 코딩 에이전트 트렌드 | 매주 월요일 아침 | 지난 7일의 에이전트 도구 신기능·릴리스 노트, 에이전트 업무 방식 사례(오케스트레이션·메모리·검증·E2E·사내 도구의 MCP화·비용), 주목할 스킬·MCP | ① 핵심 3줄 ② 항목별 변경/중요성/출처 ③ 우리 적용 후보 ≤5(난이도·효과·첫 시도) |
| 에이전트 실패 사례·안티패턴 수집 | 격주(매월 1일·15일) | 지난 14일의 에이전트 사고·보안·품질 함정·대책 수집 → **우리 가드 목록과 대조** | ① 핵심 3줄 ② 사례 표(막힘·일부·안 막힘 + 근거) ③ 보강 제안 ≤3(수단·난이도·첫 시도) |
| [1회] 모델·가격 변화와 위임 라우팅 점검 | 지정 일시 1회 | 공식 문서 기준 모델 단가·컨텍스트·지원 종료·도구의 모델 기능 → 우리 역할별 모델 배분 유지/변경 판정 | 모델 표 + 역할별 유지·변경 권장 ≤3 |
| [1회] 레거시 이관 AI 활용 사례 | 지정 일시 1회 | 레거시 로직의 이해·문서화·호출 그래프, 이관 검증(골든셋·섀도 실행), 스케줄러 이관 사례, 도구 | 항목별 사례 + 적용 ≤5 |
| [1회] DB 분석용 AI 도구 동향 | 지정 일시 1회 | 실행계획 해석·계획 회귀 탐지 도구, 읽기 전용 안전장치, 스키마 의미 카탈로그 | 도구 표 + 적용 ≤5 |

### B. 로컬 예약 작업(활성 2)

| 작업 | 주기 | 하는 일 | 출력 |
|---|---|---|---|
| 주간 세션 회고 | 금요일 오후(+지터) | 지난 7일 세션 기록·정정 로그에서 **반복 실수**(정정·훅 차단·되돌림·비효율) 추출 → 2회 이상만 개선 후보, 강제 수준 판정 + 에이전트 도구 변경 내역 7일분을 내 설정과 대조 + 입력 훅(모드) 효과 점검 (+ 규칙 감량 후보 — 나중에 정한 항목, 템플릿에만 넣었다) | 회고 문서 1개 |
| 주간 팀 문서 후보 | 금요일 오후, 회고 30분 뒤 | 이번 주 일일노트·메모리에서 팀 문서에 공유할 절차·도메인 지식·확정 정책 선별 → 기존 문서 검색으로 중복 확인 → 신규/갱신 후보 표 + 상위 3건 초안 | 후보 문서 1개 + 초안 ≤3 |

금요일 두 작업을 30분 간격으로 두고, 사람은 그 결과를 다음 주 첫 근무일 [주간 개선 점검](08_weekly-improvement-loop.md)에서 한꺼번에 본다.

## 재사용 골격

모든 루틴 프롬프트는 같은 여섯 단으로 쓴다.

1. **입력(읽기만)** — 읽을 파일·경로, 읽는 방법(큰 로그는 통째로 읽지 말고 스크립트로 추려서)
2. **찾을 신호 / 조사 대상** — 무엇을 찾는지 목록으로
3. **판정 기준** — 후보로 올리는 문턱, 분류 기준, 대조할 현재 상태
4. **출력** — 파일 경로 하나와 형식을 고정(또는 「최종 답변만」)
5. **금지** — 수정·커밋·PR 금지, 가릴 정보
6. **마지막 답변 형식** — 만든 파일 경로와 제목 몇 줄만

## 설계 포인트

| 포인트 | 내용 | 이유(Why) |
|---|---|---|
| 판정 기준을 프롬프트에 넣는다 | 「우리 현재 가드: <우리 가드 목록>」「우리 스택: <우리 스택>」을 프롬프트에 적고, 사례마다 막힘/일부/안 막힘을 매기게 한다 | 그러지 않으면 일반 뉴스 요약이 나온다. 넣으면 **내 환경과의 차이 분석**이 나온다 |
| 빈 주 처리 규칙 | 「창 안에 새 소식이 없으면 없다고 쓰고, 적용 후보는 1~2개월 범위에서 찾는다」 | 억지로 채우기와 환각을 막는다 |
| 조사 창을 계산으로 | 첫 단계에서 `date -u`로 오늘 날짜를 확인하고 창(7일·14일)을 계산한다 | 모델이 날짜를 추정하면 창이 어긋난다 |
| 1회성 숙제는 지정 일시 1회 실행으로 | 조사 숙제를 던지고 끝나면 자동으로 비활성이 된다 | 반복 루틴으로 걸어 두고 잊는 일을 막는다 |
| 2회 이상만 후보 | 회고는 같은 유형이 2회 이상 나온 것만 올린다 | 1회성 사건에 규칙을 만들지 않는다 |
| 「규칙은 있는데 또 어김」은 따로 분기 | 문구 추가가 아니라 강제 수단(훅 > 스킬 단계 > 규칙 문구)을 검토한다 | 문구를 더해도 같은 실수가 반복됐다 |
| 검색 0건은 「중복 미확인」 | 팀 문서 후보의 중복 확인에서 검색 0건을 「없음」으로 단정하지 않는다 | 다른 이름으로 이미 있을 수 있다 |
| 입력은 읽기 전용, 출력은 경로 하나 | 규칙·메모리·훅·설정 수정, 커밋·PR은 금지. 제안만 하고 반영은 사람이 고른 뒤 다른 세션에서 | 무인 실행이 설정을 바꾸면 추적할 수 없다 |
| 큰 세션 로그는 스크립트로 추려 읽는다 | 사용자 메시지와 도구 오류만 추출한다(스크립트는 임시 폴더에) | 통째로 읽으면 컨텍스트가 넘친다 |
| 넣는 것/빼는 것을 명시 | 팀 문서 후보에서 개인 작업 방식·미결·일회성 추출은 제외한다 | 기준이 없으면 무엇이든 후보가 된다 |
| 식별값은 가린다 | 개인정보·실제 식별 번호·비밀값은 `***`나 자리표시자 형태로 | 회고·초안 문서가 공유될 수 있다 |

## 만들 때의 절차

1. 프롬프트를 여섯 단 골격으로 쓴다.
2. **등록 직후 한 번 즉시 실행**해 출력 형식을 확인한다.
3. 달력 조건이 있는 루틴(그 주 첫 근무일·월말 전 근무일)은 **가정 날짜로 리허설**한다. 실제로 리허설에서 세 군데를 고쳤다.
4. 한계를 적어 둔다 — 원격 실행 환경은 네트워크 허용 목록 밖의 원문을 못 읽는다. 자동 승인 모드가 「지금 바로 실행」을 거부하면 사용자가 손으로 한 번 돌린다.
5. 지표와 판정일을 정한다(2주 뒤 유지·조정·제거).

## 다른 환경으로 옮길 때

| 루틴 | 이식성 | 바꿀 것 |
|---|---|---|
| 클라우드 트렌드·실패 사례 루틴 | 높음 | 「우리 상황·우리 가드」 단락을 새 환경의 스택·가드로 교체하면 된다 |
| 1회성 조사 루틴 | 템플릿으로만 | 도메인 문구를 걷어 내고 「상황 / 조사 대상 / 출력 형식 / 규칙」 4단 골격만 쓴다 |
| 주간 세션 회고 | 중간 | 세션 로그 경로·형식(특정 에이전트 도구의 기록 형식 전제), 규칙 파일 경로, 입력 훅 점검 절을 그 환경 것으로 |
| 주간 팀 문서 후보 | 낮음~중간 | 문서 폴더 체계·템플릿·일일노트 구조에 강하게 묶인다. 「입력·기준·중복 확인·출력·금지」 골격만 재사용한다 |

## 운영하면서 생긴 규칙

- **어느 계정·어느 세션에 걸었는지 메모리에 적는다.** 루틴이 다른 계정에 걸려 있으면 현재 세션의 조회가 빈 목록을 돌려준다. 이것을 「결과 없음」으로 넘겼다가 지적받았다. 조회가 안 되면 「그 세션이 안 떠 있어 확인 못 함」이라고 말한다.
- **의도적으로 켜 둔 루틴을 끄자고 제안하지 않는다.** 「이 계정에서는 뺐다」와 「저 계정에는 켜 뒀다」는 충돌이 아니다.
- 예약 업무 결과를 물으면 그 루틴이 걸린 세션에 메시지로 묻는다(세션 목록 확인 → 메시지 전송).
- 만료된 1회성 알림은 지워도 된다. 목록을 주기적으로 훑어 죽은 항목을 정리한다.
- 루틴이 만든 후보는 **사람이 고른 것만** 반영한다. 채택·기각은 그날 일일노트에 한 줄 남긴다.

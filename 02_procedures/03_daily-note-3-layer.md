# 일일노트와 3층 구조

기록을 세 층으로 나눈다. 층마다 역할이 다르고, 서로를 대신하지 않는다.

| 층 | 역할 | 수명 | 누가 읽나 |
|---|---|---|---|
| **일일노트** | 시간축 원재료 — 그날 받은 말·돌린 쿼리·확인한 사실 | 그날 쓰고 월 단위로 보관 | 사람(노트 앱), 다음 날 업무 보고, 주간 회고 |
| **메모리** | 현재 상태 — 과제가 지금 어디 있고 다음에 무엇을 하나 | 항상 최신으로 덮어쓴다 | 에이전트(세션 시작 시 자동 로드) |
| **주제 문서** | 분석 정본 — 설계·실측 쿼리·결정 근거 | 과제가 끝나면 보관 폴더로 | 사람과 에이전트(필요할 때) |

**Why** 메모리에 날짜 이력을 쌓았더니 과제 파일이 천 줄을 넘었고, 그 안에 이미 있던 확정 정책을 찾지 못해 결함 후보로 다시 제기했다. 반대로 일일노트를 상태 정본으로 쓰면 「지금 어떤 상태인가」를 알려고 며칠 치를 거슬러 읽어야 한다.

**규칙**
- 일일노트를 상태 정본으로 삼지 않는다.
- 날짜 이력을 메모리 파일에 누적하지 않는다. 메모리에는 최신 상태만, 경위는 그날 일일노트로.
- 일일노트에서 정리된 것만 메모리(확정된 상태·결정)와 주제 문서(분석)로 승격한다.

## 일일노트 구조

템플릿: [`templates/daily-note.md`](../templates/daily-note.md)

| 절 | 넣는 것 |
|---|---|
| **지금 상황**(전 과제 브리핑) | ① 능동 과제 4칸 표(과제 / 지금 상태 / 막힌 것·대기 / 다음 첫 손) ② `대기: 과제 — 막힌 것(PR·담당)` 한 줄 불릿 ③ `오늘 첫 손` 한 줄 |
| 오늘 건드린 주제 | 주제 목차 문서 링크만 — 걸어 두면 그 문서의 백링크에 날짜순 타임라인이 쌓인다 |
| 받은 것 | 지시·구두 전언·회신. 결정에 쓰인 구절만 「」로 인용하고 전문은 주제 문서로 |
| 실행·실측 | 돌린 쿼리와 결과(창·판정 같이). 위임은 위임 시점에 1줄 |
| 확인한 것 | 코드·DB로 근거를 확인한 사실(승격 후보) |
| 미결·다음 | 회신 대기, 판단 보류, 내일 첫 손 |

### 「지금 상황」 블록

**규칙** 그날 첫 기록 때 메모리에서 **한 번** 렌더링하는 스냅샷이다. 일중에는 고치지 않는다(변동은 「미결·다음」과 메모리에만). 전날 것을 복사해 붙이지 않는다. 렌더링 순서는 날짜 지난 `⏳` 점검 → 메모리 갱신 → 표 렌더링.

**Why** 사용자가 다른 업무를 보다 들어와도 이 블록만 보면 전 과제가 잡혀야 한다. 메모리 파일은 노트 앱에서 보이지 않으므로 「메모리 참고」 같은 포인터로 대신할 수 없다. 일중에 계속 고치면 스냅샷이 아니라 두 번째 상태 저장소가 되어 메모리와 어긋난다.

## 쓰는 방법

**규칙** 쓰기는 **작업 묶음 끝에 한 번**. 발언·정정마다 쓰지 않는다. 중간 정정·철회는 남기지 않고 최종 결과만 적는다. 한 줄은 160자 안팎. 추가는 편집 도구 대신 셸 append(`cat >> 노트 <<'EOF'`)로 섹션 끝에 붙인다.

**Why** 사용자 발언마다 노트를 고쳤더니 편집 diff(긴 줄 + 앞뒤 문맥)가 터미널을 채웠다. 하루 41회 편집, 한 줄 추가에도 화면 10행 이상. 「묶음 끝 1회 + append」로 바꾼 뒤 편집 도구 사용은 사용자 메시지 100개당 37회에서 0에 가깝게 줄었다.

묶음 안에서 기록할 것은 넷이다.

| # | 무엇 | 어디에 |
|---|---|---|
| ① | 지시·구두 전언·회신 | `받은 것` — 결정에 쓰인 구절만 「」 인용 |
| ② | 쿼리 실행 결과 | `실행·실측` — 창(기간)과 판정을 같이 |
| ③ | 코드·DB로 근거를 확인한 사실 | `확인한 것` |
| ④ | 결정 확정 또는 미결 변동 | `미결·다음` + 메모리 현행화(확정 후 1회) |

덧붙임
- `미결·다음` 줄 끝 괄호는 메모리 **밖**에 반영했을 때만 적는다(예: 팀 문서에 반영한 PR). 「(메모리)」 같은 표기는 쓰지 않는다 — 메모리 반영은 기본이라 정보가 없다.
- 두 번째 에이전트가 같은 노트에 쓸 때는 섹션 끝 append만 하고 줄 머리에 `[에이전트 이름]`을 붙인다.
- 제목의 요일은 추정하지 말고 명령으로 계산한다(`date -d <날짜> +%a`). 이틀 치 요일을 틀리게 적은 일이 있었다.
- 내부 관리(메모리 정리)와 보고 문구(업무 보고 목록)는 노트에 적지 않는다. 원재료가 아니기 때문이다.

### 이 방식의 부작용(솔직하게)

- append는 항상 파일 끝에 붙는다. 그래서 「받은 것/실행/확인」 절 구분이 흐려지고, 줄 머리의 접두어(`[받음]`·`[실행]`·`[확인]`·`[미결]`)로 절을 대신하게 됐다.
- 같은 문장이 두 번 붙거나, 같은 날 뒤집힌 결정의 앞뒤 줄이 둘 다 남는 일이 생겼다. 묶음 끝에 붙이기 전에 그날 노트의 끝부분을 한 번 본다.
- 처음에 있던 말미의 「승격 체크리스트」는 며칠씩 비어 있다가 사라졌다. 형식만 남은 절은 지운다.
- 「지금 상황」 표에 변동 없는 「리뷰·머지 대기」 행이 두 주 동안 같은 문구로 반복됐다. 표에는 능동 과제만 두고 대기는 한 줄 불릿으로 내린다.

## 보관과 뷰

- 루트에는 **이번 달 노트만** 둔다. 달이 바뀌어 그 달 첫 노트를 만들 때 지난달 노트를 `YYYY-MM/` 폴더로 옮긴다. 노트 앱의 내부 링크는 파일명 기준이라 옮겨도 깨지지 않는다.
- 프론트매터의 `status`·`category`를 고정값으로 둔다(예: `status: 기록`, `category: 일일노트`). 진행 중 문서 목록·문서 현황 뷰에 노트가 섞이지 않게 하기 위해서다.

## 메모리 이력의 1회 압축

이미 날짜 이력이 쌓인 메모리 파일은 **파일당 한 번** 압축한다.

1. 「함정·확정 사실·금지/주의」 불릿과 **file:line이 든 줄은 원문 그대로** 메모리에 남긴다.
2. 이력은 주제 폴더의 이관 문서(`NNN_메모리이관_결정이력_<날짜>.md`)로 통째 옮긴다. 줄을 삭제·이동만 하고 문장을 다시 쓰지 않는다.
3. 압축 전후로 file:line 패턴 개수를 검색으로 대조한다. 줄면 되돌린다.
4. 최상단에 「현재 상태 스냅샷(날짜)」과 「확정 정책·결정 표」를 고정한다.

**Why** 문장을 다시 쓰면 요약 과정에서 근거 위치가 사라진다. 이 방식으로 과제 파일 두 개가 각각 절반 이하로 줄었고 원문 줄 누락은 0이었다.

## 이 구조가 다른 루틴의 입력이 된다

| 루틴 | 일일노트에서 읽는 것 |
|---|---|
| 일일 업무 보고 | 직전 근무일 노트 전체 + 「내일 첫 손」 |
| 주간 팀 문서 후보 | 「확인한 것」「실행·실측」 중 팀이 따라 할 절차·지식 |
| 효과 측정 | 기록 줄의 유형 키워드(분석/구현/장애 대응/문서)로 세션 분류 |

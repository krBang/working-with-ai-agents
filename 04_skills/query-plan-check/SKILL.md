# 운영 쿼리 사전 점검

> 공개판에는 딸린 스크립트가 없다. 스크립트를 실행하는 단계는 설명을 참고해 자기 환경에 직접 구현한다.
> 원래 용도: 사용자가 DB 클라이언트로 운영에서 직접 돌릴 실측 쿼리를 넘기기 전에, 「취소가 안 먹는 풀스캔」을 만들 쿼리를 걸러 내는 일.
> 채울 값: `big_tables.txt`(운영 기준 대형 테이블), `query_check.json`(키 컬럼·개발 환경 접속 서비스·스키마), 필요하면 인덱스 정의 파일. PostgreSQL 계열 기준이다.

운영 쿼리 규칙(EXPLAIN 한 벌·MATERIALIZED 소집합·인덱스 근거)을 **문구 대신 검사로** 확인한다.

## 언제
- 운영에서 돌릴 쿼리를 사용자에게 넘기기 **직전**(문서 산출물에 넣기 전)
- `EXPLAIN` 실행계획 텍스트를 점검할 때 → `--plan` 점검

## 자동 실행(훅)
- 분석 문서(`.md`)를 Write·Edit하면 PostToolUse 훅 `sql_check.py`가 ```sql 블록을 점검한다(Edit은 바꾼 블록만). ⛔면 훅이 막아 알려 주고, ⚠는 한 줄로 전달된다.
- 훅은 정적 점검만 한다. 실행계획 점검(`--plan`)과 훅 범위 밖 경로의 쿼리는 아래 절차대로 직접 돌린다.

## 절차
0. **목표 값 대조(보정·원복·상태 조회 쿼리)** — 스크립트가 못 잡는 것이라 넘기기 전에 표로 직접 적는다.
   - `사용자가 말한 상태 이름` ↔ `쿼리의 코드값` ↔ `코드표 조회 결과` 3열. 코드 이름이 사용자 말과 다르면 넘기지 말고 고친다.
   - 같은 주제의 기존 실측 문서가 있으면 그 형태(CTE 구성·출력 컬럼·판정 기준 위치)를 따른다 — 새 형태로 바꿀 땐 이유 한 줄.
1. 쿼리를 스크래치패드 `.sql`에 저장한다(문서 본문은 그대로 `.md`).
2. 실행: `python -P <이 스킬 폴더>/check.py <쿼리.sql> [--plan <계획.txt>] [--dev-plan] [--index-file <인덱스.json>]`
   - 기본 = SQL 정적 점검 + 인덱스 정의 대조(개발 환경 카탈로그 또는 인덱스 파일)
   - `--plan` = EXPLAIN 텍스트 점검(가장 확실)
   - `--dev-plan` = 개발 환경 EXPLAIN(FORMAT JSON). 개발 환경은 행 수가 작아 **계획 모양은 참고만**
3. 판정 처리
   - `⛔`가 있으면 쿼리를 고친다. 고칠 수 없으면 사용자에게 넘기지 말고 이유를 말한다.
   - `⚠`는 고치거나, 그대로 둘 이유를 쿼리 주석·문서에 한 줄 적는다.
   - 결과의 「진입 가능 인덱스」를 문서의 인덱스 근거로 쓴다.
4. 종료 코드: 0 = 통과, 1 = ⚠, 2 = ⛔.

## 점검 항목

| 판정 | 조건 | 이유 |
|---|---|---|
| ⛔ | 대형 테이블에 걸린 조건·조인에 어떤 인덱스의 선두 컬럼도 없다 | 운영 풀스캔. 취소가 먹지 않을 수 있다 |
| ⛔ | (`--plan`) 계획에 대형 테이블 Seq Scan이 있다 | 위와 같다 |
| ⚠ | 대형 테이블 둘 이상을 조인하는데 MATERIALIZED 소집합도 키 리터럴도 없다 | 양쪽 전량 정렬·병합 계획이 나온다 |
| ⚠ | MATERIALIZED CTE와 EXISTS/NOT EXISTS가 같이 있다 | semi/anti join으로 평탄화되어 MATERIALIZED가 무력화된다 |
| ⚠ | 키 리터럴 없이 `LIMIT 1` | row-goal 계획으로 오히려 느려진다 |
| ⚠ | (`--plan`) MATERIALIZED CTE가 계획에 CTE로 안 보인다 / Limit 아래 Index Scan이 Filter로 거른다 | 인라인·평탄화, row-goal |
| ℹ | `IN (SELECT …)`, 선두 컬럼이 범위 조건인 인덱스, 조인 추정 rows=1 | 참고. 위험 판정은 운영 계획으로 |

## 한계
- 정규식 기반이라 복잡한 서브쿼리 별칭은 놓칠 수 있다 — `⛔`가 안 나왔다고 안전하다는 뜻은 아니다. 운영 EXPLAIN이 정본이다.
- 선택도(값이 얼마나 좁히는지)는 모른다. 대형 테이블 목록은 `big_tables.txt`(운영 기준, 새로 확인되면 추가).
- 매퍼 파라미터(`#{…}`)가 든 SQL은 점검하지 않는다. 값을 채운 운영 쿼리 형태로 바꿔서 돌린다.

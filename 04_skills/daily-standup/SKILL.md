# 전일/금일 업무 정리(팀 공유 문서 보고용)

> 공개판에는 딸린 스크립트가 없다. 스크립트를 실행하는 단계는 설명을 참고해 자기 환경에 직접 구현한다.
> 원래 용도: 매일 아침 팀 공유 문서에 붙여 넣는 전일/금일 업무 보고. 그날의 메모리 정리와 주간·월초 정기 점검을 이 스킬에 얹어 「업무 시작」 한마디로 돌린다.
> 채울 값: `<docs-vault>`(노트 볼트 경로), `<memory-dir>`(메모리 폴더), `<workspace>`(레포들이 있는 폴더), 티켓 대장 조회 수단(있으면).

## 0. 메모리 정리 먼저
- 시작하자마자 `memory-tidy` 스킬을 실행한다(매일 오전 1회, 묻지 않음). 보고는 목록 끝 「끝맺음」에 한 줄로 붙인다.
- 같은 날 이미 돌았으면(그날 대화에서 결과 줄을 냈으면) 건너뛴다.

## 월초 브랜치 정리(그달 첫 근무일만)
- 업무 목록 뒤에 `python -P <이 스킬 폴더>/branch_tidy.py --workspace <workspace> --memory-index <memory-dir>/MEMORY.md --out <docs-vault>/_docs/개인/브랜치정리/브랜치정리_YYYYMMDD.md`를 돌려 후보 표만 보여 주고 지울 것을 묻는다(읽기 전용 스크립트).
- 후보 = **내 작업**(끝 커밋 작성자 = 그 레포 `user.email`)이면서 운영 브랜치에 머지됐거나, 원격이 삭제되고 고유 커밋이 없는 것. 메모리 「활성 작업」의 티켓·보존 대상·미커밋 worktree·커밋 0개 브랜치는 스크립트가 제외한다.
- 고른 것만 `git worktree remove <경로>` → `git branch -d <브랜치>`(미머지·미커밋이면 git이 거부한다). `-D`·`--force`·원격 브랜치 삭제는 하지 않는다. 결과는 그날 일일노트 한 줄.

## 주간 개선 점검(그 주 첫 근무일만)
- 기준일이 **그 주 첫 근무일**이면 업무 목록을 낸 뒤 이어서 한다. 월초의 작업 방식 정기 점검도 이 자리에서 함께 한다.
- ① 외부: 주간 트렌드 루틴의 그 주 결과를 받는다(루틴이 걸린 세션에 메시지로 묻는다. 세션이 없으면 「확인 못 함」 한 줄 — 「결과 없음」으로 단정하지 않는다). 이어서 대조 두 가지.
  - 설치 플러그인 대조: 설치 버전과 각 플러그인 릴리스 노트를 비교해, 새 버전의 변경 중 우리 작업에 닿는 것만 고른다.
  - 에이전트 도구 신기능 대조: 설치 버전 + 공식 변경 내역의 지난 7일 릴리스. 두 갈래로 고른다 — **영향**: 우리 훅·권한·스킬·예약 작업의 동작이 바뀌는 것 / **새로 쓸 것**: 새 기능이 지금의 불편이나 수작업을 덜어 주면 사용자가 묻기 전에 ③ 후보로 올린다. 날짜가 확인된 항목만.
- ② 내 방식: 가장 최근 주간 회고 파일(금요일 로컬 예약 작업의 산출물) + 지난주 일일노트·피드백 메모리 변경·같은 지적의 반복.
- ③ 출력 = 「이번 주 적용 후보」 1~3건 — 각각 무엇·왜(①/② 근거)·**바꿀 곳(설정·훅·스킬·규칙 파일 경로)**·첫 손·규모. ①을 그대로 옮기지 않는다. 우리 작업에 맞는 것만. 승인하면 그 자리에서 진행한다. 채택·기각 결과는 그날 일일노트 `미결·다음`에 한 줄.
- ④ 팀 문서: 가장 최근 팀 문서 후보 파일(금요일 로컬 예약 작업의 산출물)의 후보 표를 그대로 보여 주고 반영할 것을 묻는다. 고른 것만 초안을 다듬어 문서 레포 브랜치·1커밋·PR. 파일이 없으면 「후보 없음」 한 줄.
- ⑤ 도구 주간 패치: 도구 메모리의 `⬜보정 후보`를 모아 보여 주고, 한 주 치를 **한 번에** 패치할지 묻는다. 승인하면 구현 위임 1회 → 테스트·실사용 재생 → 설치본 갱신 → 1커밋·PR. 후보가 없으면 「보정 후보 없음」 한 줄.

## 입력
1. 기준일 = 보고하는 날(보통 다음 근무일). **전일 = 직전 근무일 일일노트**, **금일 = 그 노트의 「내일 첫 손」(없으면 `미결·다음` 중 본인 할 일) + 사용자가 대화에서 확정한 할 일**
   - 일일노트 `<docs-vault>/_docs/일일노트/YYYY-MM-DD.md`(월초면 지난달 폴더)
2. 진행 상태 확인 = `MEMORY.md` 활성 작업 줄(완료/진행 구분)
3. 티켓 대장(조회 도구가 있을 때) — 기본 전월 1일~오늘·진행 중 건 포함
   - 티켓이 있는 과제는 **과제 이름을 대장의 제목과 똑같이** 쓴다
   - 대장 상태와 메모리가 어긋나면 목록은 메모리 기준으로 쓰고, 「끝맺음」에 어긋난 티켓만 한 줄로 알린다(대장은 고치지 않는다)
   - 조회가 안 되면 1·2만으로 작성하고 그 사실을 한 줄 덧붙인다

## 작성 규칙
- 형식:
  ```
  * 전일
     * <과제 이름>
        * <세부>
  * 금일
     * <과제 이름>
  ```
- **코드블록이 아니라 렌더링되는 목록**으로 출력하고, **같은 내용을 HTML(`<ul>`·`<a href>`)로 스크래치패드에 써서 클립보드에 넣는다** — 터미널의 마크다운 링크는 복사해도 문서 도구에서 하이퍼링크가 되지 않는다. 명령: `powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File <이 스킬 폴더>\set_clip_html.ps1 -Path <html 경로>`(출력 = 클립보드 조각 앞부분). ⛔`Set-Clipboard -AsHtml`은 쓰지 않는다 — 한글이 깨져 붙은 적이 있다
- PR·팀 문서는 **하이퍼링크**로: `[레포 PR 번호](<PR 주소>)`. 주소를 확인하지 못했으면 그 사실을 한 줄 덧붙인다
- **넣지 않는 것**: 리뷰·머지·운영 반영 대기 같은 남의 손 일, 내부 판단용 대기(⏳ 회신 대기 등), 개인정보·고객 식별값
- 전일은 **한 일**(개발·테스트·분석·부작용 확인·문서 공유) 위주로 과제별 묶음. 끝난 과제는 「완료」로 쓴다
- 금일은 **본인이 할 일**만. 결과물 계획이 있으면 함께 쓴다(예: 「… 테스트 완료 및 결과 공유」)
- 금일에 **추정으로 할 일을 만들지 않는다** — 확정된 할 일(기한·지시가 있는 것)이나 사용자가 하자고 한 것만. 「대기가 풀리면 할 수도 있는」 과제는 넣지 않는다
- 공유 채널에 그대로 쓰기 애매한 건(예: 특정 고객 요청 데이터 보정)은 일반화 문구 대안을 한 줄로 제시한다

## 끝맺음
- 목록 뒤에 판단이 필요한 항목(뺄지·넣을지)만 1~2줄. 일일노트에는 기록하지 않는다(보고 문구는 원재료가 아니다)

## 왜 이렇게 됐나
| 규칙 | 계기 |
|---|---|
| 그날 첫 「업무 시작」은 이 스킬이 먼저 | 스킬이 안 불리고 세션 점검부터 도는 날이 있었다 → 입력 훅으로 실행 지시를 붙였다 |
| HTML로 클립보드에 | 터미널 링크를 복사하면 문서 도구에서 링크가 죽었다 |
| 남의 손 일은 넣지 않는다 | 「리뷰·머지 대응은 안 써도 된다」는 지적 |
| 금일은 확정된 것만 | 대기 중인 과제의 테스트를 금일 할 일로 적었다가 지적받았다 |
| 조회 실패를 「결과 없음」으로 쓰지 않는다 | 다른 계정에 걸린 루틴을 조회해 빈 목록을 받고 결과 없음으로 넘겼다 |

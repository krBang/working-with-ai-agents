# 메모리 정리(매일 오전, daily-standup 앞에서)

> 공개판에는 딸린 스크립트가 없다. 스크립트를 실행하는 단계는 설명을 참고해 자기 환경에 직접 구현한다.
> 원래 용도: 세션마다 자동으로 로드되는 메모리 인덱스가 로드 한도를 넘지 않게, 과제 상태 줄만 골라 매일 줄이는 일.
> 채울 값: `<memory-dir>`(메모리 폴더), `<rules-file>`(항상 로드되는 함정 파일), 백업 폴더 위치.

규칙 정본: 워크스페이스 규칙 파일의 「판단/보고」·「일일노트」 절, 메모리의 인덱스 크기 규칙.
내부 관리라 **사용자에게 묻지 않는다.** 단 아래 「묻는 것」만 예외.

## ⛔ 손대지 않는 것(일하는 방식 = 코어)

정리 대상은 **「활성 작업」·「종결」 절의 과제 상태 줄뿐**이다. 아래는 크기가 커도 줄이지·옮기지·합치지·지우지 않는다.
- MEMORY.md 「작업 방식(피드백)」「사용자」「참조」「기술 지식」「보존 가드」「즉시 참조 함정」 절의 줄
- `type: feedback`·`type: user`·`type: reference` 메모리 파일 본문 전부
- 프로젝트 rules 파일, 규칙 문서(`CLAUDE.md`), 스킬
- 과제 파일의 함정(⛔·★) 구절 — 옮겨 받기만 하고 지우지 않는다

한도를 못 맞추면 이 구역을 건드리지 말고 3절대로 묻는다. **Why:** 일하는 방식이 깎이면 잘하던 일을 갑자기 못하게 된다.

## 1. 측정(명령 1회)

```bash
python -P <이 스킬 폴더>/measure.py --memory-dir <memory-dir> --rules <rules-file>
```

출력: 인덱스 바이트/상한 · 줄 수/200 · 긴 줄(줄 번호·바이트) · 끊긴 링크 · 고아 파일.

## 1-1. 백업(고치기 전에 반드시)

- 바꿀 파일(MEMORY.md + 옮겨 받을 과제 파일)을 `<memory-dir>`와 나란한 `memory-backup/YYYYMMDD/`에 그대로 복사한다. 메모리 폴더 **밖**에 둔다(안에 두면 같은 내용이 두 번 불려 온다).
- 백업 없이 고치지 않는다. 같은 날 두 번째 정리면 `YYYYMMDD-2/`.

## 2. 정리 기준(순서대로, **목표 18KB 안팎**까지 — 22KB 한도 밑에서 멈추지 않는다)

| # | 대상 | 처리 |
|---|---|---|
| 1 | 끊긴 링크 | 파일명이 바뀐 것이면 고치고, 파일이 없으면 링크만 걷어 낸다(줄 내용은 둔다) |
| 2 | 900바이트 넘는 활성 작업 줄 | 지난 경위·커밋 해시·검체·✅완료 단계를 **과제 메모리 파일 최상단 「현재 상태 스냅샷」**으로 옮긴다. 인덱스 줄에는 「지금 상태 · 다음 · ⏳대기 · `작업물:`」만 남긴다(목표 300자 이내) |
| 3 | 과제 파일이 없는 과제의 긴 줄 | 경위가 오늘(또는 해당 날짜) 일일노트에 있으면 지우고, 없으면 과제 파일을 새로 만들어 옮긴다 |
| 4 | 종결 과제 | 인덱스에 두지 않고 종결 목록 파일로 옮긴다(링크 + 한 구절). 인덱스 「종결」 절은 그 파일 링크 한 줄만 |
| 5 | 결정이 뒤집힌 옛 문구 | 지운다(「(이전)」 보존 금지) |

- **옮길 때 문장을 다시 쓰지 않는다** — 줄(구절)을 그대로 잘라 옮긴다. `file:line`이 든 구절은 원문 그대로.
- 옮기기 전후로 `grep -c`로 `file:line` 패턴(예: `\.(sql|java|xml|js|ts|py):[0-9]`) 개수를 인덱스 + 대상 파일 합계로 대조한다. 줄면 되돌린다.
- **다른 방식으로도 확인한다** — 옮긴 구절마다 대상 파일에 원문 그대로 있는지 문자열 일치로 확인한다(하나라도 없으면 백업에서 되돌림). 받는 쪽에는 「인덱스에서 이동(MM-DD)」 머리말을 붙이고, 인덱스 줄에는 그 과제 파일 링크를 남겨 어디로 갔는지 따라갈 수 있게 한다. 링크할 파일이 없으면 옮기지 않는다.
- 「보존 가드」 절과 「먼저 언급 금지」 표시 줄은 **손대지 않는다**.
- 날짜 이력을 인덱스에 누적하지 않는다 — 날짜는 최신 상태 표기(「(MM-DD)」)만.

## 3. 묻는 것(이것만)

- 정리해도 한도 미만이 안 될 때 — 어느 과제를 종결/보관으로 내릴지는 업무 판단이라 한 번에 묶어 묻는다.
- 날짜가 지난 `⏳타팀(…~MM-DD)` — daily-standup의 세션 시작 점검과 같이 한 줄로.

## 4. 보고

- 결과는 **한 줄**: 「메모리 정리: N → M B · 긴 줄 k개 과제 파일로 이동(원문 일치 확인) · 백업 `memory-backup/YYYYMMDD` · 끊긴 링크 0 · 고아 1(xxx.md)」.
- 고아 파일은 지우지 않는다 — 보고만 한다(보존 가드·참조용일 수 있다).
- 일일노트에는 쓰지 않는다(내부 관리).

# 브리지 메시징 — 두 에이전트가 서로에게 말 걸기

원본 스크립트: `to_codex.py` · `to_claude.py` · `bridge_register.py`(공개판에는 코드가 없고 설계만 적는다)

## 구조

```
                    ┌───────────────── 레지스트리(sessions.json) ─────────────────┐
                    │  claude.name = <현재 세션 이름>   codex.thread = <대화 ID>   │
                    └───────────────────────────────────────────────────────────┘
   Claude 세션 ── to_codex.py ──▶ codex queue --thread <id> --message "<머리말 + 본문>" ──▶ Codex 대화
   Claude 세션 ◀── SendMessage ── 일회용 claude -p(ListAgents → SendMessage) ◀── to_claude.py ── Codex
```

- **Claude → Codex**: Codex 앱의 큐 명령으로 대상 대화에 메시지를 넣는다.
- **Codex → Claude**: 실행 중인 Claude 세션끼리는 메시지를 주고받을 수 있다. 그래서 **전달만 하는 일회용 Claude 세션**을 띄워 세션 목록을 확인하고 대상에게 보낸다.
- **레지스트리**: 세션 이름과 대화 ID는 세션마다 바뀐다. 현재 값을 한 파일에 적어 두고 바뀌면 갱신한다.

## 메시지 형식

```
[발신→수신 | 과제ID | 요청/회신/완료 | 답할 곳] 본문
```

| 종류 | 뜻 |
|---|---|
| 요청 | 착수 요청 |
| 회신 | 접수·질문·중간 결과 |
| 완료 | 산출물과 완료 기준 확인 결과 |

「접수했습니다」(회신)와 「끝났습니다」(완료)를 종류로 가른다. 접수 회신만 보고 작업이 끝난 줄 아는 일을 막는다.

## 설계 결정과 이유

| 결정 | 이유 |
|---|---|
| 긴 본문(약 2천 자 초과)은 파일로 쓰고 경로만 보낸다 | 명령줄 길이 제한과 따옴표 손실. 메시지 폴더는 양쪽이 모두 읽을 수 있는 곳에 둔다 |
| 실행 파일 경로를 **실행할 때마다** 찾는다 | 앱이 업데이트되면 설치 경로의 버전이 바뀐다. PATH에 없는 경우도 있다 |
| 수신자는 이름을 **확인한 뒤** 지정한다 | 내부 식별자를 직접 넣어 전송이 실패했다 |
| 전달용 세션은 가장 싼 모델, **사용자 설정·훅·MCP·슬래시 명령·세션 저장을 모두 끄고**, 도구는 「세션 목록」「메시지 전송」 둘만 허용한다 | 처음에는 일회용 세션이 사용자 플러그인 훅·MCP·프로젝트 규칙·메모리를 전부 불러와 느렸다. 게다가 상대 에이전트의 메시지가 「사용자 정정」 로그에 섞였다 |
| 전달용 세션은 **워크스페이스 밖 임시 폴더**에서 실행한다 | 프로젝트 지침과 메모리를 불러오지 않게 한다 |
| 프롬프트는 표준 입력으로 넘긴다 | 도구 목록 옵션이 가변 인자라 뒤에 오는 프롬프트를 삼킨다 |
| 「한 글자도 바꾸지 말고 보내라」고 지시하고 결과는 `SENT`/`NOT_FOUND`만 출력하게 한다 | 전달자가 내용을 요약·수정하지 않게 한다 |
| `--dry-run`·`--check`를 둔다 | 전송 없이 실행 파일·대상·최종 메시지를 확인하고, 세션 이름만 조회할 수 있다 |

실측: 전달용 세션의 세션 목록 조회 한 번이 몇 초, 비용은 무시할 만한 수준이었다.

## 원본 스크립트 인터페이스(참고)

공개판에 스크립트는 없다. 자기 환경에 만들 때 참고할 인자 설계만 적는다.

- **레지스트리 갱신**(`bridge_register.py`): 현재 Claude 세션 이름, Codex 대화 ID와 제목을 인자로 받아 레지스트리 파일을 고친다. 세션이 바뀌었을 때 돌린다.
- **Claude → Codex**(`to_codex.py`): 과제 ID, 종류(요청·회신·완료), 답할 곳, 본문(직접 문자열 또는 파일)을 받는다. 긴 본문은 파일로 넘긴다.
- **Codex → Claude**(`to_claude.py`): 같은 인자에 본문 문자열을 받는다. 워크스페이스 밖에서 실행한다. 전송 없이 실행 파일·대상만 확인하는 `--check`를 둔다.

`NOT_FOUND`가 나오면 세션 이름이 바뀐 것이다. 레지스트리를 갱신한다.

## 요청서에 넣는 것

메인이 보조에게 일을 넘길 때 본문(파일)에 넣는 항목:

- 사용자 승인의 원문과 적용 범위(있을 때)
- **무엇을 하면 안 되는지** — 부재 중 커밋·푸시·PR·티켓·DB 쓰기 금지 등
- 담당 분리 — 「이 파일들은 당신 단독」「이 파일들은 건드리지 말 것(내 담당)」
- 읽기 전용 여부, 메인이 쓰고 있는 작업 폴더 목록
- 산출 문서 경로
- 보고 방식 — 항목이 끝날 때마다 회신 1회, 전부 끝나면 완료. 막히면 사용자가 아니라 메인에게 묻는다(사용자 부재 시)
- 사용자 할 일 블록 규칙

템플릿: [`templates/handoff-message.md`](../templates/handoff-message.md)

## 알려진 제약

- 큐로 들어간 메시지는 받는 쪽 화면에서 **사용자 턴처럼 보인다.** 그래서 「상대의 메시지는 사용자 입력이 아니다」를 규칙으로 못 박는다. → [역할과 승인 전달](03_roles-and-approval-relay.md)
- 앱 상태 DB에서 최신 대화를 찾는 폴백은 앱 버전에 따라 깨질 수 있다. 레지스트리나 `--thread`로 지정하는 것이 기본이다.
- 두 도구의 CLI 옵션은 버전에 따라 바뀐다. 옮겨 심을 때 플래그부터 확인한다.

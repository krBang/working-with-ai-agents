# 업무 보고 형식 — 일일

팀 공유 문서에 붙여 넣는 정기 보고의 형식. 스킬: [`daily-standup`](../04_skills/daily-standup/SKILL.md)

## 1. 일일 보고(전일/금일)

```
* 전일
   * <과제 이름>
      * <한 일 — 개발·테스트·분석·부작용 확인·문서 공유>
   * <과제 이름> 완료
* 금일
   * <과제 이름>
      * <결과물 계획이 있으면: … 테스트 완료 및 결과 공유>
```

| 규칙 | 이유(Why) |
|---|---|
| 전일 = 직전 근무일의 일일노트, 금일 = 그 노트의 「내일 첫 손」 + 사용자가 확정한 할 일 | 보고를 기억이 아니라 기록에서 만든다 |
| 과제 이름은 티켓 대장의 제목과 **똑같이** | 팀이 같은 이름으로 찾는다 |
| 전일은 **한 일** 위주, 과제별 묶음. 끝난 과제는 「완료」 | |
| 금일은 **본인이 할 일**만 | |
| 금일에 **추정으로 할 일을 만들지 않는다** — 기한·지시가 있는 것, 사용자가 하자고 한 것만 | 대기 중인 과제의 다음 단계를 금일 할 일로 적었다가 지적받았다 |
| **넣지 않는다**: 리뷰·머지·반영 대기 같은 남의 손 일, 내부 판단용 대기(⏳), 개인정보·식별값 | 「리뷰·머지 대응은 안 써도 된다」 |
| PR·문서는 하이퍼링크로 | 번호만 있으면 읽는 사람이 찾아야 한다 |
| 대장 상태와 메모리가 어긋나면 목록은 메모리 기준, 어긋난 건만 끝에 한 줄 | 대장은 에이전트가 고치지 않는다 |
| 공유하기 애매한 건은 일반화 문구 대안을 한 줄로 | |

### 붙여넣기까지가 일이다

- 터미널에는 **렌더링되는 목록**으로 보여 준다(코드블록이 아니다).
- 같은 내용을 **HTML로 만들어 클립보드에** 넣는다. 터미널의 마크다운 링크는 복사해도 문서 도구에서 하이퍼링크가 되지 않는다.
- 운영체제의 HTML 클립보드 형식을 직접 만든다. 셸의 간편 옵션은 한글이 깨져 붙은 적이 있다. 넣은 뒤 클립보드에서 다시 읽어 앞부분을 확인한다. → `set_clip_html.ps1`

### 끝맺음

목록 뒤에 판단이 필요한 항목(뺄지·넣을지)만 1~2줄. 메모리 정리 결과 한 줄. 보고 문구 자체는 일일노트에 기록하지 않는다.

## 2. 주간(사람에게 가는 것은 아니지만)

금요일 자동 회고와 팀 문서 후보는 **문서 하나**로 떨어지고, 마지막 답변은 파일 경로와 제목 몇 줄뿐이다. 사람은 다음 주 첫 근무일에 일일 보고 뒤에서 한꺼번에 본다. → [주간 개선 루프](../02_procedures/08_weekly-improvement-loop.md)

## 3. 공통

- 보고는 **기록에서** 만든다(일일노트·메모리·대장). 기억에서 만들지 않는다.
- 에이전트가 만든 보고를 사용자가 그대로 붙일 수 있어야 한다. 손으로 고칠 곳이 있으면 형식 규칙이 덜 된 것이다.
- 형식 교정을 받으면 스킬 파일을 고친다(메모리에만 적지 않는다). 스킬은 고치면 바로 반영된다.

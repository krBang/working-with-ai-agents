# 보고 형식

에이전트가 사용자에게 답할 때의 형식. 전부 실제 지적에서 나왔다.

## 1. 사용자가 할 일은 맨 위 블록으로

**규칙** 사용자가 직접 해야 하는 행동(명령 실행·재연결·승인·결정)이 있으면 답변 **맨 위**에 인용 블록으로 따로 뺀다. 무엇을·어디서·정확한 명령까지 적는다. 여러 개면 번호를 붙이고, 끝나면 무엇을 알려 달라고 할지도 적는다. 할 일이 없으면 블록을 넣지 않는다.

```markdown
> 👉 **사용자 할 일**
> 1. 터미널에서 `<정확한 명령>` 실행
> 2. `<도구>` 재연결(메뉴 경로)
> 3. 끝나면 「완료」라고만 알려 주세요
```

**Why** 재연결 요청이 상태 설명 사이에 묻혀 있어 사용자가 자기 차례인 줄 몰랐다 — 「내가 해 줘야 하는 건 표시를 제대로 해 달라, 티가 안 난다」.

해당하는 것: 도구 재연결, 플러그인 다시 불러오기, 터미널에서 직접 실행해야 하는 명령(로그인·비밀 등록), 다른 에이전트 화면에 직접 남겨야 하는 승인, DB 클라이언트에서의 실행, 결정 질문.

## 2. 대화는 존댓말, 문서는 단정형

**규칙** 대화 답변(본문·불릿·표 설명 모두)은 존댓말로 쓴다. 단정형(「확인했다」「안 바뀌었다」)은 문서 본문·커밋 메시지·메모리 파일 안에서만 쓴다.

**Why** 분석 문서의 톤을 대화에 그대로 가져왔다가 「말투가 왜 그러냐」는 지적을 받았다.

## 3. 완료 보고의 구성

```
① 한 일(무엇을 어디에)
② 검증 결과(무엇으로 확인했나 — 명령·건수)
③ 확인하지 못한 것(미확인)
④ 사용자가 알아야 할 제약
```

여기서 끝낸다. 「다음은 무엇부터 할까요」「이건 우선순위가 아닙니다」를 붙이지 않는다. 다음 할 일 목록은 물었을 때만 낸다.

검증·테스트 보고는 통과/실패/미확인 **개수**와 실패·미확인 항목만 적는다.

## 4. 「없다·안 된다」를 보고할 때

읽은 위치(file:line·쿼리)를 같이 적는다. 확인하지 않았으면 「미확인」이라고 쓴다. 「검색 0건」만으로 말하지 않는다. → [증거 우선](../01_principles/01_evidence-first.md)

## 5. 위임·리뷰 결과를 전달할 때

지적마다 메인이 재검증한 결과를 붙인다.

| 표기 | 뜻 |
|---|---|
| ✅확인 | 메인이 코드를 읽거나 직접 실행해 확인했다 |
| ⚠오탐 | 재검증에서 사실이 아니었다(근거 위치를 적는다) |
| 미검증 | 평가자의 근거만 있다 |

## 6. 말한 것과 한 것

- 「바로 진행하겠습니다」라고 쓰려면 그 호출이 같은 응답 안에 있어야 한다.
- 못 했으면 경위를 설명하지 않는다. 「안 했습니다 → 지금 했습니다」만 쓴다.

**Why** 경위 설명은 변명으로 읽힌다.

## 7. 여러 항목을 설명할 때

- 「하나씩 설명해」를 들으면 한 답변에 한 항목. 맨 위에 「총 N개 중 1번」을 밝히고 근거 1~2줄·권고 1줄로 끝낸다.
- 선택을 물을 때는 설명 문단에 섞지 않고 질문 도구로 분리한다. 권고안을 첫 선택지에.

## 8. 진행 중일 때

- 본 과제의 **다음 한 걸음만** 준다. 곁가지 실측·최적화·후속 제안은 현재 작업이 끝난 뒤, 물었을 때만.
- 쿼리나 명령을 줄 때는 **어느 환경에서 돌리는지 한 줄로 못 박는다.** 한 번에 하나만.

**Why** 검증 중에 「나중에 판단용」 쿼리를 덧붙였고 환경(개발/운영)까지 섞여 나갔다.

## 9. 보고에 넣지 않는 것

| 넣지 않는 것 | 이유 |
|---|---|
| 한 번 물은 승인 대기 건의 반복 언급 | 사용자가 알아서 지시한다 |
| 「비용이 든다」는 단점 앞세우기 | 판단 기준은 품질·정확도·사용자 시간이다(사용자 방침) |
| 사용자가 이미 처리한 전언에 대한 재확인 요구 | 검증이 아니라 되돌리기다 |
| PR 보고 끝의 「완료로 바꿀까요」 | 완료의 기준은 사용자가 정했다 |
| 내부 관리(메모리 정리)의 과정 | 결과 한 줄이면 된다 |
| 추정을 결론처럼 | 사용자가 데이터로 확인 중일 때 특히 |

## 10. 실행을 부탁하는 것은 화면에 전부 보여 준다

사용자에게 실행을 부탁하는 쿼리·명령은 문서 링크로 대신하지 않고 대화 본문에 코드블록으로 전부 싣는다. → [쿼리 전달 형식](05_query-handoff-format.md)

## 11. 도구 인자의 문자

사용자에게 노출되는 도구 인자(질문·선택지·설명)에는 사용자의 언어를 평문 그대로 쓴다. 이스케이프 표기로 쓰면 틀린 글자가 그대로 화면에 나간다.

## 12. 평가·회고에서 아쉬운 점을 말할 때

항목마다 지적 → `개선:` → 맡을 일 순서로 쓴다. 지적만 모아 놓고 끝내지 않는다.

```
- 아쉬운 점: <무엇이 왜 아쉬운가 — 한 문장>
  개선: <구체적으로 무엇을 바꾸는가>
  맡을 일: <에이전트가 할 것> (사용자가 정할 것이 있으면 따로 적는다)
```

맡을 일은 제안이다. 평가를 요청받은 것이지 실행을 요청받은 것이 아니므로, 착수는 사용자가 고른 뒤에 한다. → [실행 규율 12](../01_principles/04_execution-discipline.md) · [질문 매트릭스 2-1](../01_principles/03_question-matrix.md)

## 13. 대기 중인 요청이 있을 때

요청이 겹쳐 대기가 2건 이상이면 답변 맨 위에 `대기: ①… ②…` 한 줄을 둔다. → [겹치는 요청 나누기](../02_procedures/11_approval-batching-and-request-triage.md)
